# kosta-ai-lab 공개 포털 — 기획

## 목표와 범위

첫 사이트는 학습 플랫폼이 아니라 오픈소스 조직과 활동을 소개하는 공식 입구다. 로드맵을 보여 주고, 지금 제공하는 자료로 연결한다. 이 문서는 구현 계획이며 완료 보고가 아니다.

- 공개 저장소: `kosta-ai-lab/ai-native-sdlc`. 조직 표기는 GitHub 식별자 `kosta-ai-lab`을 쓴다.
- 대상: 개발 경험자를 중심으로 하되 비개발자도 포함한다.
- 첫 공개 범위: 조직·공개 취지 소개 → 전체 로드맵 → 현재 제공 서비스·자료 연결 → 참여 안내.
- 별도 브랜치와 Draft PR에서 제작·검토한다. PR 생성은 main 병합이나 사이트 배포를 뜻하지 않는다.
- 목표 호스팅은 GitHub Pages다. 별도 서버·회원가입·유료 서비스 없이 작동하는 정적 사이트로 만든다.
- 기존 모듈·강의 원본과 담당자·초안 상태를 보존한다. 공개 저장소의 실제 자료만 연결하며, 없는 실습이나 확인되지 않은 서비스를 제공 중인 것처럼 표시하지 않는다.

## 화면 구성

메뉴는 소개 / 로드맵 / 서비스·자료 / 참여하기다.

1. **첫 화면:** "AI와 함께 만드는 소프트웨어, 함께 발전시키는 개발 방식"과 취지 두 문단, 버튼 "로드맵 둘러보기"·"공개 자료 보기"를 둔다. 내부 제작·검수 용어는 노출하지 않는다.
2. **소개:** "왜 함께 공개하나요?" — 워크숍에서 출발한 AI-Native SDLC 프로젝트와 세 가지 원칙(경험을 나눕니다 / 결과를 확인합니다 / 함께 보완합니다)을 소개한다.
3. **로드맵:** 큰 영역 다섯 개(문제·요구사항 → 명세·설계 → AI와 구현 → 테스트·검증 → 배포·운영)를 보여 준다. 영역을 선택하면 주요 주제와 관련 프로젝트·자료가 열린다. 에이전트 하니스와 임베디드는 관련 영역에 연결되는 확장 주제다. 이 흐름은 전체를 이해하기 위한 개요이며 고정 학습 순서가 아니다. 세부 주제의 선후관계는 기존 자료를 대조해 정하기 전까지 표시하지 않는다.
4. **서비스·자료:** "지금 살펴볼 수 있는 것" — AI-Native SDLC 프로젝트, 강의자료와 실습(공개 강의 4개), 요구사항부터 테스트까지 연결하는 코드 예제. 각 항목을 실제 제공 유형으로 표시한다. 코드 예제는 웹 앱 실행 서비스가 아니다.
5. **참여하기:** "작은 수정부터 새로운 사례까지" — 기여 방법, 오류·개선 제안, GitHub 조직 방문, 라이선스 요약을 둔다.
6. **하단:** GitHub · 기여 안내 · 라이선스 · 보안 안내.

## 상태 표시 원칙

- 로드맵 주제의 "공개 자료 있음 / 준비 중"은 그 주제에 연결된 실제 공개 자료가 있는지를 뜻하며, 사람의 진도가 아니다. 모듈의 완성도는 따로 보여 준다. 모듈 원문 상태(초안·시드 모듈)와 담당, 목적이 작성 전인지는 각 주제 위치에 원문 그대로 보인다. 목적이 비어 있는 README만으로는 "공개 자료 있음"으로 표시하지 않는다.
- 공개 항목은 "공개됨 / 준비 중", 운영 서비스는 "운영 중 / 준비 중"으로 유형에 맞게 표시한다. 운영 여부를 확인하지 않은 서비스는 목록에 넣지 않는다. 현재 운영 서비스의 이름과 URL은 확인되지 않아 공개 목록에 없다.
- 가짜 통계·학습자 수·완료 시간·검증 실적은 넣지 않는다.

## 갱신 대응

- 화면 틀과 콘텐츠를 분리한다. 소개 문구는 문서(HTML)로, 로드맵 영역·주제·공개 항목은 일정한 형식의 데이터로 관리한다.
- 공통 콘텐츠 항목에 id와 관련 영역을 적으면 로드맵과 서비스·자료 목록에 함께 반영된다. 새 영역은 기존 링크를 깨뜨리지 않고 추가한다. 이전 시안의 `#stage/NN` 링크는 해당 영역으로 이어진다.
- 수정 → PR 검토 → 병합 → Pages 반영 흐름을 목표로 한다. 링크·데이터 형식·빌드를 검사하며, 자동 배포는 실제 설정과 실행을 확인하기 전에는 완료로 표현하지 않는다.
- CMS·관리자 화면·회원·DB·학습 진도·자동 수집·알림·상시 모니터링은 이번 범위에 넣지 않는다.

## 첫 공개에서 제외

새 웹 교재 전면 집필, 자체 실습 플랫폼, 회원가입, 진도·수료 관리, 자동 평가, AI 튜터, 모든 자료의 사이트 내부 재제작. 필요해지면 후속 범위로 따로 검토한다.

## 디자인 방향

- 분위기: 명료함, 전문성, 탐색의 즐거움.
- 중심 표현: 큰 영역이 한 줄로 이어지고, 선택한 영역이 강조되며, 확장 주제가 가지로 연결되는 지도.
- MotionSites 보유 스킬의 구성·타이포그래피·모션 기법을 참고하되 기존 브랜드·이미지·정확한 레이아웃을 복제하지 않는다. 외부 미디어·폰트·CDN·광고는 쓰지 않는다.
- 장식용 영상보다 지도·연결선·정보 전환에 모션을 쓴다. 첫 콘텐츠는 즉시 보이게 한다.
- 모바일에서는 세로 흐름으로 바꾸고, 키보드 탐색·명확한 포커스·동작 줄이기 설정을 지원한다.
- 문장은 자연스러운 한국어로 쓴다.

## 구현과 배포 원칙

- `site/` 안에 정적 사이트를 구성한다. 기술 선택은 단순성과 유지보수를 우선한다. 세부 명세는 [LEARNING_SITE_DESIGN.md](LEARNING_SITE_DESIGN.md), 운영 절차는 [LEARNING_SITE_OPERATIONS.md](LEARNING_SITE_OPERATIONS.md)에 있다.
- 기존 교재를 복제하지 않고 GitHub 원본으로 연결하며, 링크와 상태 표시의 근거를 기록한다.
- Pages 프로젝트 하위 경로(`/ai-native-sdlc/`)에서 CSS·JavaScript·내부 이동이 정상 작동해야 한다.
- 배포 산출물에는 사이트 파일만 넣는다. 저장소 전체·감사 자료·개인 자료는 배포하지 않는다.
- PR에서는 정적 검증만 하고 배포하지 않는다. main 병합 이후의 배포 워크플로와 설정 절차를 마련한다.
- Pages 활성화·main 병합·첫 실서비스 배포는 검토 후 따로 진행한다.
- 라이선스는 교육자료 CC BY-NC 4.0 / 코드 Apache 2.0 구분과 제3자 예외를 유지한다.

## 완료 기준

- 승인된 포털 초안이 실제 화면으로 동작한다. 로드맵 영역은 실제 원본 자료로 연결된다.
- 데스크톱·모바일에서 화면을 렌더하고 직접 확인한다.
- 메뉴 이동, 영역 선택, 내부 이동, 키보드 탐색, 동작 줄이기, 프로젝트 하위 경로를 실제로 시험한다.
- 모든 원본 자료 경로가 Git 추적 파일에 있으며, 초안·준비 중 상태를 과장하지 않는다.
- 민감 정보·비공개 자료·불필요한 대용량 파일이 추가되지 않았음을 변경분에서 확인한다.
- Draft PR, 실제 열람 가능한 미리보기, 실행한 검사 결과와 미검증 범위를 전달한다.
