# web-task-system — 사내 업무 관리 시스템 (레퍼런스 앱)

> AI Native SDLC 방법론의 **관통 레퍼런스 애플리케이션**입니다.
> 하나의 기능("할 일 생성")이 방법론 모듈 03~06을 실제로 관통하는 과정을, 동작하는 코드로 실증합니다.

## 무엇을 보여주는가

첫 기능 "할 일 생성"이 요구사항에서 동작 코드까지 이어지는 전 과정입니다. 각 단계는 이전 단계를 입력으로 받아 다음으로 넘깁니다.

| 단계 | 모듈 | 산출물 |
|------|------|--------|
| 요구사항 | 03 | `docs/03-requirements.md` (유즈케이스 UC-01, R-01~R-03) |
| 명세 | 04 | `docs/04-spec.md` (Todo 모델, createTodo 시그니처) |
| 인수조건 | 05 | `docs/05-acceptance.feature` (Gherkin) |
| 테스트·구현 | 06 | `test/todo.test.ts`, `src/todo.ts` |

요구사항 R-01~R-03이 명세로, 명세가 인수조건으로, 인수조건이 테스트로 1:1 이어지며 추적성이 유지됩니다.

## TDD 실증 (Red-Green)

06 모듈의 핵심 원칙대로, 테스트를 먼저 작성하여 실패를 확인한 뒤 최소 구현으로 통과시켰습니다.

1. Red — 구현 없이 테스트를 실행하여 `Cannot find module '../src/todo'` 실패를 먼저 확인
2. Green — 04 명세대로 최소 구현을 작성한 뒤 테스트 실행: **2 tests passed**

명세에 없는 필드나 동작은 추가하지 않았습니다. 이것이 AI의 환각을 억제하는 핵심입니다.

## 실행 방법

```
pnpm install
pnpm test
```

동작 확인 결과: 테스트 2건 통과, 타입 체크(tsc) 통과.
