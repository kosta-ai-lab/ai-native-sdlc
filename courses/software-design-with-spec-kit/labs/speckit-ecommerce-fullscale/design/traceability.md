# 추적성 매트릭스

요구사항(유스케이스)에서 설계 산출물·ADR·기능 스펙·구현·테스트까지 한 줄로 잇는다. Spec Kit `/tasks`·`/analyze` 단계가 이 표를 만들고 검증한다. "설계가 코드로 빠짐없이 이어졌는가"를 눈으로 확인하는 장치.

| # | 요구사항 (유스케이스) | 설계 산출물 | ADR | 기능 스펙 | 상태 |
|---|---|---|---|---|---|
| R1 | 멀티셀러 주문 생성·분할 | 도메인(Order/SubOrder), 시퀀스 | ADR-001 | 004-multiseller-order | 설계 |
| R2 | 결제 전 재고 선점 | 상태머신, 시퀀스 | ADR-002 | 004-multiseller-order | 설계 |
| R3 | 결제 승인·취소(멱등) | 시퀀스, 상태머신 | ADR-003 | 005-payment | 설계 |
| R4 | 배송 처리·완료 | 유스케이스, 상태머신 | ADR-004 | 006-shipping | 설계 |
| R5 | 판매자 정산(수수료 공제) | 도메인(Settlement), 시퀀스 | ADR-001, 004 | 007-settlement | 설계 |
| R6 | 환불·정산 역산 | 상태머신 | ADR-004 | 008-refund | 설계 |

> 상태 값: 설계 → 스펙 → 구현 → 테스트 → 완료. 강의에서는 R1(주문 분할)을 라이브로 스펙→구현→PR→머지까지 한 바퀴 돌리고, 나머지는 완성본으로 리뷰한다.
