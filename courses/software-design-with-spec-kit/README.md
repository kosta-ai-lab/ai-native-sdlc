## 왜 이 과정인가

AI가 코드를 대신 쓰는 시대에, 사람이 쥐고 있어야 할 것은 설계 결정입니다. 이 과정은 "설계가 코드보다 먼저"라는 명제를 하루 동안 산출물로 증명합니다.

관통 사례는 **멀티셀러 마켓플레이스**입니다. 여러 판매자의 상품을 한 번에 담아 한 번 결제하면, 시스템은 이를 판매자별로 나눠 배송·정산·환불까지 각각 책임져야 합니다. 이 하나의 요구가 유스케이스·데이터·상태·구조에 어떤 결정을 강제하는지 따라갑니다.

장표는 다이어그램을 크게 펼친 뒤 **읽고 → 해석하는** 2단 구성입니다. 그림을 보는 데서 멈추지 않고, 그 그림이 어떤 결정을 내렸고 무엇을 기각했는지를 ADR로 확인합니다.

## 학습 목표

1. 좋은 설계의 기준(응집도·결합도·변경 용이성·명시적 경계·트레이드오프)을 설명한다
2. Spec Kit의 각 단계에서 어떤 설계 산출물이 나오는지 지도로 그린다
3. 유스케이스·도메인 모델·ERD·시퀀스·상태머신·컴포넌트 다이어그램을 직접 만든다
4. 산출물에 담긴 설계 결정을 ADR 형식(결정·근거·기각한 대안·결과)으로 읽어 낸다
5. 요구사항 ↔ 설계 ↔ 작업의 추적성 매트릭스를 만들고 이슈로 분해한다
6. 이슈 → 브랜치 → PR → 리뷰 → 머지 사이클을 한 바퀴 돌린다

## 관통 요구사항 여섯 가지

멀티셀러 주문 분할 · 결제 전 재고 선점 · 멱등 결제 · 판매자별 배송 · 수수료 정산 · 환불 역산.

이 여섯이 추적성 매트릭스의 R1~R6이며, 각각 어떤 설계 산출물과 ADR로 이어지는지 하루 내내 따라갑니다.

## 실습 자산

`labs/speckit-ecommerce-fullscale/`에 완성 저장소가 들어 있습니다. Spec Kit이 생성하는 템플릿·스크립트·스킬은 사본을 두지 않았으니, 실습 전에 `specify init`을 먼저 실행하십시오(자세한 절차는 `labs/README.md`).
