# 과정 설계에 반영할 원칙과 검증 과제

## 추천 과정 포지셔닝

### 제안 제목

**TDD Harness Engineering — BDD 명세부터 검증 가능한 AI 코딩 루프까지**

### 한 줄 설명

BDD 예제를 실패 테스트로 변환하고, 역할·상태·Hook·품질 게이트를 통해 AI 코딩 에이전트가 Red–Green–Refactor와 회귀 검증을 지키게 만드는 실습 과정.

### 기존 과정과의 차이

| 기존 영역 | 중심 | 본 과정의 차별점 |
|-----------|------|------------------|
| 일반 TDD | 개발자의 테스트 우선 습관 | 에이전트가 규율을 우회하지 못하게 환경 설계 |
| 테스트 자동화 | 테스트 생성·실행 도구 | 요구 추적, 역할 분리, 단계 전이, 완료 차단 |
| BDD/Cucumber | 예제와 실행 가능한 명세 | 인수조건을 TDD 및 하니스 상태와 연결 |
| 하니스 입문 | 에이전트·스킬·Hook 구성 | 테스트 피드백 루프라는 구체적 문제에 적용 |
| MoAI 사용법 | 완성 도구 사용 | 구조를 해부하고 최소 하니스를 직접 재구성·검증 |

## 권장 학습목표

수료자는 다음을 할 수 있어야 한다.

1. BDD의 Discovery–Formulation–Automation과 TDD의 관계를 설명한다.
2. 인수조건을 추적 가능한 실패 테스트로 변환한다.
3. test-writer, implementer, reviewer의 권한과 책임을 분리한다.
4. Red 증거와 테스트 결과를 세션 상태로 기록한다.
5. 테스트 실패 시 완료를 차단하는 Hook을 구현하고 동적으로 검증한다.
6. 신규 기능 TDD와 레거시 Characterization Test를 구분한다.
7. MoAI-ADK 같은 대형 하니스를 구성요소와 품질 게이트 관점에서 평가한다.

## 추천 관통 시나리오

현재 `samples/web-task-system`의 “할 일 생성”을 확장한다.

### 1단계 — BDD

- 정상 제목 생성
- 빈 제목 거부
- 제목 앞뒤 공백 처리
- 중복 정책 결정
- 저장 실패 처리

### 2단계 — TDD

- 인수조건 ID를 테스트에 연결
- 의미 있는 Red 확인
- 최소 구현
- 작은 리팩터
- 전체 회귀 확인

### 3단계 — 하니스

- 구현 역할의 테스트 파일 수정 차단
- Red 증거 없는 완료 차단
- 테스트 실패 상태에서 완료 차단
- 승인된 테스트 변경 예외 흐름

### 4단계 — 하니스 검증

- Hook 응답 형식 오류 주입
- timeout 유도
- 테스트 단언 약화
- 관련 테스트 누락
- 각 실패를 하니스가 탐지하는지 확인

## 반드시 비교할 실험

같은 기능을 다음 세 조건에서 수행하고 결과를 비교한다.

| 조건 | 제공 환경 | 관찰 항목 |
|------|-----------|-----------|
| A | “TDD로 구현해” 프롬프트만 제공 | Red 누락, 테스트 수정, 회귀 |
| B | TDD 스킬과 체크리스트 제공 | 절차 준수와 증거 품질 |
| C | 역할 분리 + 상태 + Hook 게이트 제공 | 우회 가능성, 재현성, 비용 |

이 비교가 있어야 하니스의 가치가 단순한 주장에 머물지 않는다.

## 과정 범위 선택안

### 4시간 — 핵심 체험

1. BDD와 TDD 연결
2. test-first 스킬 작성
3. test-writer/implementer 분리
4. 완료 게이트 구현
5. 실패 주입 데모

### 8시간 — 권장 실전 과정

4시간 범위에 다음을 추가한다.

- Example Mapping과 인수조건 품질
- 계층형 테스트 전략
- Characterization Test
- mutation/negative control
- MoAI-ADK 구조 분석
- 프롬프트-only 대 하니스 비교 실험

### 16시간 — 심화 과정

- 팀 단위 병렬 에이전트와 worktree 격리
- 테스트 영향 분석
- CI/PR 게이트 연결
- 하니스 관찰성·메트릭
- 조직 표준 템플릿 제작

## 현재 권고

첫 버전은 8시간으로 설계하는 것이 적절하다. BDD를 독립 과목처럼 깊게 다루기보다 첫 90분에 예제와 인수조건을 만들고, 나머지를 TDD 하니스 제작·검증에 사용한다. MoAI는 설치법 강의가 아니라 완성형 사례 해부와 실패 게이트 검증에 사용한다.
