# U-02 — 유효한 Red 판정

## 표준 학습경험 계약

| 항목 | 내용 |
|---|---|
| 유형 | 문제 진단형 |
| 권장 시간 | 35분 |
| 선수 수행 | 테스트 명령을 실행하고 assertion 결과를 읽을 수 있다 |
| Knowledge | `K-VALID-RED` |

## 수행목표

제공된 세 가지 실패 로그와 테스트 코드를 보고, 수강자는 유효한 Red와 실행·환경 오류를 구분하고 각 판정의 근거를 세 조건으로 설명한다. 세 사례 모두 정확히 판정해야 한다.

## 성공 증거

- 각 사례를 `VALID_RED`, `INVALID_EXECUTION_ERROR`, `INVALID_ALREADY_GREEN` 중 하나로 분류한다.
- 실행 가능성, 관찰 타당성, 원인 일치 중 어떤 조건이 충족 또는 위반됐는지 기록한다.
- 유효하지 않은 사례에 다음 행동을 제안한다.

## 학습경험 패턴

이 단원은 동일한 8단계 강의 골격 대신 문제 진단형 패턴을 사용한다.

```text
서로 다른 빨간 결과 제시
→ 개인 판정
→ 판정 기준 도출
→ 기준을 새 사례에 적용
→ 자동 gate의 최소 데이터 설계
```

## 진행

1. 강사는 색상과 exit code가 같은 두 실패 로그를 보여준다.
2. 수강생은 어느 로그가 구현 시작을 허용하는지 먼저 선택한다.
3. 코드와 전체 로그를 공개해 실행 오류와 assertion failure를 구분한다.
4. 세 조건의 판정 모델을 정리한다.
5. 수강생은 새로운 세 사례를 독립적으로 판정한다.
6. 마지막으로 하니스가 저장해야 할 evidence field를 제안한다.

## 대표 오개념

- 빨간 출력이면 모두 Red다.
- 테스트 파일이 먼저 생성됐으면 test-first다.
- 실패 이유는 실행 후 결과에 맞춰 기록해도 된다.
- 처음부터 통과한 테스트도 회귀 테스트이므로 Red로 인정할 수 있다.

## 표준과 변형의 경계

기관별로 언어, 테스트 프레임워크와 로그 형식은 바꿀 수 있다. 세 가지 판정 조건, 독립 판정 과제와 평가 기준은 유지해야 한다.
