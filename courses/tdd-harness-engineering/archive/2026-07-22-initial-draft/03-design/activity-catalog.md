# 강의 데모·실습 재료 카탈로그

## 사용 원칙

모든 데모는 성공 경로만 보여주지 않는다. 먼저 실패를 재현하고, 하니스 적용 후 같은 실패가 탐지·차단되는지를 보여준다.

## D01 — 모호한 요구와 BDD 예제

| 항목 | 내용 |
|------|------|
| 시간 | 15분 |
| 개념 | Discovery와 구체적 예제 |
| 입력 | “사용자는 할 일을 생성할 수 있다” |
| 활동 | AI에게 예외를 묻고 규칙·예제·질문을 분류 |
| 결과 | Example Map, Gherkin 시나리오 |
| 실패 주입 | 공백 제목 정책을 일부러 누락 |
| 관찰 | 구현 결과가 임의 정책을 만들어내는지 |

## D02 — 의미 있는 Red와 가짜 Red

| 항목 | 내용 |
|------|------|
| 시간 | 15분 |
| 개념 | Red 증거 |
| 입력 | 미구현 행동, 잘못된 import, 미설치 패키지 |
| 활동 | 세 실패를 실행하고 유효성을 판정 |
| 결과 | Red evidence 문서 |
| 실패 주입 | 환경 오류를 TDD Red로 제출 |
| 관찰 | reviewer가 구분해 거부하는지 |

## D03 — 테스트 세탁

| 항목 | 내용 |
|------|------|
| 시간 | 20분 |
| 개념 | 역할 분리와 테스트 불변성 |
| 입력 | 빈 제목 테스트와 실패 구현 |
| 활동 | 단일 에이전트와 권한 제한 implementer 비교 |
| 결과 | 테스트 diff, 차단 로그 |
| 실패 주입 | `toThrow()`를 `toBeDefined()`로 완화 |
| 관찰 | 하니스가 테스트 약화를 탐지하는지 |

## D04 — BDD–TDD 추적성

| 항목 | 내용 |
|------|------|
| 시간 | 20분 |
| 개념 | 요구–인수조건–테스트 연결 |
| 입력 | R-01~R-03, AC-01~AC-04 |
| 활동 | 테스트 태그와 traceability JSON 생성 |
| 결과 | 누락·고아 매핑 보고서 |
| 실패 주입 | AC 하나의 테스트 매핑 삭제 |
| 관찰 | 완료 게이트가 누락을 차단하는지 |

## D05 — 프롬프트-only 대 하니스

| 항목 | 내용 |
|------|------|
| 시간 | 30분 |
| 개념 | 절차 지시와 실행 환경의 차이 |
| 조건 A | “TDD로 구현해”만 제공 |
| 조건 B | TDD 스킬 제공 |
| 조건 C | 역할·상태·Hook 게이트 제공 |
| 측정 | Red 증거, 테스트 변경, 회귀, 시간, 도구 호출 |
| 결과 | 비교표와 회고 |

## D06 — MoAI Plan → Run → Sync

| 항목 | 내용 |
|------|------|
| 시간 | 30분 시연 또는 60분 실습 |
| 개념 | 완성형 하니스의 상태 흐름 |
| 입력 | 할 일 생성 요구 |
| 활동 | SPEC 작성, TDD 실행, 품질 결과, 동기화 관찰 |
| 결과 | SPEC 자산, 테스트, 체크포인트, 보고서 |
| 관찰 | 선언된 workflow가 실제 Git 이력과 로그에 남는지 |

## D07 — Hook silent bypass

| 항목 | 내용 |
|------|------|
| 시간 | 25분 |
| 개념 | 하니스 자체 검증 |
| 입력 | 실패 테스트와 완료 차단 Hook |
| 실패 주입 | 잘못된 응답 JSON, exit code 덮어쓰기, 짧은 timeout |
| 결과 | 정적 검사는 PASS하지만 동적 contract test는 FAIL |
| 관찰 | fail-open과 fail-closed 차이 |

## D08 — 레거시 Characterization Test

| 항목 | 내용 |
|------|------|
| 시간 | 25분 |
| 개념 | 신규 TDD와 현재 행동 보존의 차이 |
| 입력 | 테스트 없는 제목 정규화 함수 |
| 활동 | 현재 행동 표 작성, characterization test, 리팩터 |
| 실패 주입 | 기존 버그를 정상 행동으로 고정 |
| 관찰 | 현재 행동과 원하는 행동을 누가 승인하는지 |

## D09 — 테스트 영향 분석

| 항목 | 내용 |
|------|------|
| 시간 | 20분 |
| 개념 | 관련 테스트 컨텍스트 |
| 입력 | 여러 모듈에서 공유하는 날짜 유틸리티 변경 |
| 활동 | 인접 테스트만 실행한 결과와 영향 매핑 결과 비교 |
| 결과 | 변경–테스트 맵 |
| 실패 주입 | 간접 의존 모듈 회귀 |
| 관찰 | TDD 절차만으로 회귀를 찾을 수 있는지 |

## D10 — Mutation으로 테스트 품질 검증

| 항목 | 내용 |
|------|------|
| 시간 | 20분 |
| 개념 | 테스트의 테스트 |
| 입력 | 통과하는 테스트 스위트 |
| 활동 | 비교 연산자, 경계값, 오류 분기를 변이 |
| 결과 | 생존·사망 mutation 목록 |
| 실패 주입 | 핵심 단언 제거 |
| 관찰 | 커버리지는 유지되지만 결함 탐지력은 떨어지는지 |
