# 하니스 용어 경계

## 목적

이 프로젝트에는 서로 다른 두 하니스가 존재한다. 문서에서 수식어 없이 `하니스`라고만 쓰면 강의의 주제와 강의 제작 시스템이 혼동되므로 아래 용어를 사용한다.

## 개발 하니스 — Development Harness

강의에서 학습하고 구축하는 대상이다. AI가 소프트웨어를 개발할 때 모델 바깥에서 작업 환경, 명세, 도구, 권한, 상태, 테스트, 평가, 실행 증거와 완료 조건을 통제한다.

```text
의도·명세
→ AI 구현
→ 결정적 Test
→ LLM Evaluation
→ 품질 Gate
→ 수정 또는 완료
```

대표 질문은 다음과 같다.

- AI가 만든 코드와 동작의 품질을 무엇으로 검증하는가?
- 실패·오래된 증거 상태에서 완료를 어떻게 차단하는가?
- 결정적 테스트와 LLM 평가를 어떻게 구분하고 결합하는가?
- 권한, 역할과 상태 전이를 어떻게 통제하는가?

## 과정 제작 하니스 — Course Production Harness

이 강의를 만드는 작업 환경이다. 사용자의 의도를 질문으로 발견하고, Planning·Research·Design·Manuscript·Materials·Deliveries의 산출물과 상태 전이를 통제한다.

```text
사용자 의도
→ 과정 기획
→ 조사·지식화
→ 거시·세부 설계
→ 교재·수업 자료
→ 납품·리허설
```

대표 질문은 다음과 같다.

- 사용자의 명시적 의도와 작성자의 추론을 어떻게 구분하는가?
- 앞 단계의 어떤 산출물이 있어야 다음 단계로 넘어가는가?
- 표준 과정과 기관별 변형을 어떻게 분리하는가?
- 자료가 실제 수업에 사용할 수 있는지는 어떻게 검증하는가?

## 둘의 관계

과정 제작 하니스는 개발 하니스를 설명하고 실습하는 강의를 만든다. 두 시스템 모두 상태, 증거, gate와 실패 주입이라는 공통 원리를 사용할 수 있지만 목적·대상·산출물은 다르다.

| 구분 | 개발 하니스 | 과정 제작 하니스 |
|---|---|---|
| 목적 | AI 개발 결과의 품질과 안전 통제 | 강의 제작 과정의 의도·품질 통제 |
| 주된 대상 | 코드, 명세, test, eval, agent run | brief, research, design, manuscript, material |
| 사용자 | 개발자와 AI 코딩 에이전트 | 과정 기획자, 저자, 강사와 제작 에이전트 |
| 완료 증거 | 테스트·평가 결과, trace, gate decision | 의도 승인, 출처, 정렬, 리허설 결과 |
| 강의에서의 위치 | 학습 내용 | 학습 내용을 만드는 운영 방법 |

## 작성 규칙

- 첫 언급에서는 반드시 `개발 하니스` 또는 `과정 제작 하니스`라고 쓴다.
- 같은 절에 두 개념이 함께 나오면 이후에도 수식어를 생략하지 않는다.
- `TDD 하니스`는 개발 하니스의 하위 유형으로만 사용한다.
- `콘텐츠 하니스`, `강의 하니스` 대신 `과정 제작 하니스`로 통일한다.
- 두 하니스가 공유하는 원리를 논할 때도 어느 시스템에 적용하는지 문장마다 명시한다.
