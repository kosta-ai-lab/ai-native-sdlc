# 개발 하니스

## 목적

이 문서는 TDD 과정에서 학습하고 구축할 `개발 하니스`의 개념 경계를 정리한다. 과정을 만드는 운영 시스템의 용어는 [`../../harness/terminology.md`](../../harness/terminology.md)에서 관리한다.

## 정의

강의에서 학습하고 구축하는 대상이다. AI가 소프트웨어를 개발할 때 모델 바깥에서 작업 환경, 명세, 도구, 권한, 상태, 테스트, 평가, 실행 증거와 완료 조건을 통제한다.

```text
의도·명세
→ AI 구현
→ 결정적 Test
→ LLM Evaluation
→ 품질 Gate
→ 수정 또는 완료
```

대표 질문은 다음과 같다.

- AI가 만든 코드와 동작의 품질을 무엇으로 검증하는가?
- 실패·오래된 증거 상태에서 완료를 어떻게 차단하는가?
- 결정적 테스트와 LLM 평가를 어떻게 구분하고 결합하는가?
- 권한, 역할과 상태 전이를 어떻게 통제하는가?

## 과정에서의 범위

- `TDD 하니스`는 개발 하니스의 하위 유형으로 사용한다.
- 결정적 Test와 LLM Evaluation은 서로 다른 증거로 수집하고 품질 gate에서 결합한다.
- 명세·권한·상태·증거·완료 조건을 프롬프트 밖의 통제 구조로 연결한다.
- 과정 제작 절차는 학습 내용에 포함하지 않는다.
