# 의도 중심 진행 하니스

## 목적

과정 제작 하니스는 완성 파일을 검사하는 도구만이 아니다. 사용자가 아직 완전히 언어화하지 못한 의도를 발견하고, 선택의 결과를 보여주며, 중요한 결정을 함께 확정하도록 진행해야 한다.

각 단계는 다음 대화 루프를 사용한다.

```text
Guide → Capture → Reflect → Decide → Gate
```

### Guide

현재 단계에서 결과를 크게 바꾸는 질문을 한 번에 하나씩 제시한다. 이미 문서나 대화에서 알 수 있는 내용을 다시 묻지 않는다.

### Capture

사용자의 답을 다음 네 상태로 기록한다.

| 상태 | 의미 |
|---|---|
| Explicit | 사용자가 직접 명시한 의도 |
| Inferred | 정황으로 추론했지만 아직 확인하지 않은 것 |
| Assumed | 진행을 위해 임시로 둔 가정 |
| Open | 아직 결정되지 않은 것 |

### Reflect

답을 그대로 복사하지 않고 그것이 과정 설계에 어떤 의미인지 짧게 되돌려준다.

```text
제가 이해한 의도는 X입니다.
그렇다면 Y는 포함하고 Z는 표준 과정에서 제외하는 방향이 됩니다.
```

### Decide

실제 하위 산출물을 바꾸는 선택만 결정으로 기록한다. 선택지가 있을 때는 2~3개와 각각의 영향을 제시하되, 사용자가 이미 방향을 명시했다면 불필요하게 재선택을 요구하지 않는다.

### Gate

자동 검사는 파일과 관계를 확인하고, 사용자는 핵심 의도 요약과 열린 결정을 확인한다. 사용자 승인이 필요한 단계에서는 “문서가 존재한다”가 아니라 “이 요약이 내 의도를 맞게 반영한다”가 전이 조건이다.

## 질문을 할지 판단하는 기준

다음 세 조건을 모두 만족할 때 질문한다.

1. 답에 따라 이후 과정의 범위·대상·평가·형식이 실질적으로 달라진다.
2. 기존 대화와 자료만으로 신뢰 있게 추론할 수 없다.
3. 잘못 가정했을 때 되돌리는 비용이 지금 질문하는 비용보다 크다.

다음 질문은 피한다.

- 기존 문서에 답이 있는 질문
- 표현만 다르고 같은 결정을 반복하는 질문
- 지금 단계의 산출물에 영향을 주지 않는 취향 질문
- 사용자가 판단하려면 먼저 조사 결과를 봐야 하는 질문
- 한 번에 열 개 이상의 항목을 채우게 하는 설문

## 질문의 순서

질문은 고정 체크리스트 순서가 아니라 정보 가치가 높은 순서로 한다.

```text
방향을 바꾸는 질문
→ 범위를 바꾸는 질문
→ 평가를 바꾸는 질문
→ 운영을 바꾸는 질문
→ 표현과 형식 질문
```

예를 들어 과정의 최종 수행이 정해지지 않았는데 슬라이드 장수부터 묻지 않는다.

## 응답을 산출물로 바꾸는 규칙

사용자의 자연어 답은 세 군데에 선택적으로 반영한다.

- `01-planning/intent-ledger.md`: 의도 상태와 결정 근거
- 해당 단계의 정식 산출물: brief, blueprint, Unit, delivery 등
- `01-planning/decisions.md`: 다른 단계에도 영향을 주는 장기 결정

모든 대화를 보존하지 않는다. 이후 작업에 영향을 주는 의도와 결정만 남긴다.

## 승인 방식

각 단계 종료 시 전체 문서를 다시 읽으라고 요구하지 않는다. 다음 네 항목만 요약한다.

```text
확정된 의도
이번 단계에서 내린 결정
다음 단계가 사용할 산출물
아직 열린 결정과 미룬 이유
```

사용자는 요약을 승인하거나 수정한다. 승인 후에도 새로운 근거가 나오면 결정 기록을 남기고 앞 단계로 돌아갈 수 있다.

## 하니스의 세 가지 역할

| 역할 | 하는 일 | 하지 않는 일 |
|---|---|---|
| Facilitator | 의도를 발견하는 질문과 선택의 영향 제시 | 사용자가 말하지 않은 목적 확정 |
| Editor | 답을 일관된 설계 문서로 변환 | 답을 원문 그대로 쌓기 |
| Gatekeeper | 필수 결정과 증거가 없으면 전이 보류 | 형식적 체크만으로 승인 대체 |
