# 정성 검토 체크리스트

## Intent

- 사용자가 직접 말한 의도와 작성자가 추론한 의도가 구분되는가.
- 이미 답이 있는 질문을 반복하지 않았는가.
- 질문의 답이 실제 산출물이나 결정을 바꾸는가.
- 단계 종료 요약을 사용자가 자신의 의도와 일치한다고 확인했는가.
- 열린 결정을 임의의 확정값처럼 후속 문서에 사용하지 않았는가.

## Evidence

- 인용한 출처가 바로 앞의 claim을 실제로 뒷받침하는가.
- 공식 설명, 소스에서 확인한 동작과 작성자의 해석이 구분되는가.
- 소스 파일의 존재를 실제 런타임 강제로 과장하지 않았는가.

## Knowledge

- 문서가 출처 내용을 순서만 바꿔 다시 말하는 데 그치지 않는가.
- 개념의 경계, 원인 관계, 판단 기준 또는 수행 절차가 생겼는가.
- 적용되는 상황과 적용하면 안 되는 상황이 모두 있는가.
- 구체 사례를 새로운 상황에 전이할 수 있는가.

## Canonical Design

- 최종 수행에서 거꾸로 학습경험을 도출했는가.
- 단원 제목의 나열이 아니라 난이도와 수행의 진행이 있는가.
- 각 학습경험의 필요성을 최종 평가와 연결해 설명할 수 있는가.
- 기관명, 특정 일정과 특정 기술 스택이 표준설계에 섞이지 않았는가.

## Delivery Adaptation

- 대상자의 기존 역량과 업무 맥락이 구체적인가.
- 표준설계에서 바뀐 부분과 바뀌지 않은 부분이 보이는가.
- 시간 또는 환경 제약이 학습성과를 훼손한다면 이를 숨기지 않았는가.

## Courseware

- 설명 없이 불릿만 나열된 부분이 없는가.
- 실습이 실제로 실행되며 예상 결과가 재현되는가.
- 오답 또는 실패가 진단 가능한 피드백으로 이어지는가.
- 평가 결과만 보고 학습목표 달성 여부를 판정할 수 있는가.
- 강의 시간 안에 수행 가능한지 리허설했는가.
