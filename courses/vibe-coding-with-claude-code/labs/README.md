# 실습 대본 — 하루 안에 앱 하나 완주하기

혼자서도 따라 할 수 있게 실습 세 개를 순서대로 정리했습니다. 슬라이드 없이 이 문서만 보고도 같은 결과에 도달합니다.

## 준비

```bash
# 1) Claude Code 설치 (네이티브, Node.js 불필요)
curl -fsSL https://claude.ai/install.sh | bash

# 2) 실행하면 브라우저가 열립니다 — 본인 Claude 계정으로 로그인
claude

# 3) 설치와 인증 확인
claude --version
```

구독 대신 API 키를 쓴다면 `export ANTHROPIC_API_KEY=sk-ant-...`로 설정합니다. 키는 저장소에 커밋하지 않습니다.

plugin 두 개를 미리 설치해 둡니다. 오후 실습에서 DB 연동과 배포를 자연어 한 줄로 처리하는 데 씁니다.

```
/plugin marketplace add anthropics/claude-plugins-official
/plugin install supabase
/plugin install vercel
```

## 실습 1 — 그냥 바이브

스택을 지정하지 않고, Claude가 알아서 고르게 둡니다. 무엇을 어떤 순서로 만드는지 관찰하는 것이 목적입니다.

```
할일 앱 만들어줘
```

앱이 뜨면 기능을 하나씩만 덧붙입니다.

```
삭제 버튼을 추가해줘
```

여기서 한계가 드러납니다. 요청이 쌓일수록 앞서 만든 것이 흔들리고, 무엇을 만들기로 했는지가 대화 밖에 남지 않습니다. 이 문제의식이 실습 2로 이어집니다.

## 실습 2 — 요구사항과 디자인을 먼저 세우기

먼저 요구사항을 문서로 뽑습니다.

```
할일 앱의 요구사항을 정리해줘. 대상은 직장인이고 빠른 입력과 우선순위 관리가 중요해.
```

`requirements.md`가 나오면 `Shift+Tab`을 두 번 눌러 Plan 모드로 전환하고, 그 요구사항을 근거로 앱을 다시 구성하게 합니다. 계획을 읽고 승인한 뒤 실행합니다.

이어서 UI를 올립니다.

```
/frontend-design 디자인 가이드를 적용하여 할일 목록 UI를 전문적으로 개선해줘. 우선순위별 색상 구분 포함.
```

실습 1의 결과와 나란히 놓고 비교합니다. 같은 앱인데 요구사항과 디자인 시스템이 앞에 놓이면 결과가 어떻게 달라지는지 눈으로 확인하는 단계입니다.

## 실습 3 — DB 연동과 배포

데이터가 새로고침에도 남게 만듭니다.

```
이 앱의 데이터를 Supabase에 저장하도록 연동해줘. 새로고침해도 데이터가 유지되게.
```

plugin이 마이그레이션 SQL 작성과 `.env.local` 등록까지 처리합니다. 새로고침 후에도 데이터가 남는지 확인합니다.

이제 밖에서 접속되게 만듭니다.

```
이 프로젝트를 GitHub에 올리고 Vercel에 배포해줘. Supabase 키도 환경변수로 등록해줘.
```

빌드가 끝나면 `https://*.vercel.app` 주소가 발급됩니다. 휴대폰에서도 열리는지 확인합니다.

마지막으로 다듬습니다. 오류는 메시지를 그대로 붙여 넣는 것이 가장 빠릅니다.

```
배포된 페이지에서 [에러 메시지 또는 어색한 UI]가 보여. 고쳐줘.
```

시연용 더미 데이터를 세 건쯤 넣어 두면 첫인상이 달라집니다.

## 완주 확인

- [ ] 자연어만으로 앱을 만들었다 (코드를 직접 쓰지 않았다)
- [ ] 요구사항 문서와 `CLAUDE.md`가 저장소에 남아 있다
- [ ] 새로고침해도 데이터가 유지된다
- [ ] 공개 URL이 발급되어 다른 기기에서 열린다
