# 모듈 04 — SDD(명세 기반 개발)

> 상태: 단원 7개 (도구 가이드 5개, SDD 도구를 설치하지 않는 단원 2개)
> 한 줄: **요구사항을 구현과 테스트가 따를 명세로 구체화하고, 그 명세를 개발의 기준으로 계속 쓴다.**

## 목적

요구사항이 “제목이 있는 할 일을 생성할 수 있다”라면 명세는 입력 형태, 반환값, 초기 상태, 오류 조건을 정해 구현하는 사람과 테스트를 쓰는 사람이 같은 결과를 예상하게 합니다. 이 모듈은 명세를 쓰고 검토한 뒤 구현과 검증에 계속 사용하는 흐름을 다룹니다. 문서만 만들어 두거나 도구의 작업 목록을 모두 체크했다고 해서 명세를 충족한 것은 아닙니다.

학습 후에는 다음을 할 수 있어야 합니다.

- 모듈 03의 요구·UC·결정·미결을 읽고 구현 계약으로 구체화한다.
- 정상 동작과 오류 동작, 데이터 제약을 명세하고, 요구 → 명세 → 인수조건 → 테스트로 이어지는 추적성을 확인한다.
- 변경이 생기면 문서와 코드의 영향 범위를 찾아 모듈 05(BDD)와 모듈 06(TDD)에 넘긴다.

## 단원 구성

도구 가이드는 하나만 골라도 됩니다. 단원마다 README와 GUIDE가 있습니다(M03은 환경별 GUIDE 네 개). 설치·계정·버전은 각 단원의 사전 준비물을 따릅니다.

| 단원 | 내용 | 만든 사람 |
|---|---|---|
| [M01 — Kiro](M01-kiro/) | Kiro: IDE 안에서 하는 SDD | 이선아 교수 |
| [M02 — OpenSpec](M02-open-spec-01/) | OpenSpec: 변경 단위로 관리하는 SDD | 이선아 교수 |
| [M03 — Spec Kit](M03-spec-kit/) | Spec Kit: 단계별 SDD | 이선아 교수 |
| [M04 — GSD](M04-gsd/) | GSD: 컨텍스트를 관리하는 SDD | 이선아 교수 |
| [M05 — BMAD](M05-bmad/) | BMAD: 역할 에이전트가 협업하는 SDD | 이선아 교수 |
| [M06 — 요구사항에서 명세·설계·구현 검증으로](M06-requirements-to-spec/) | SDD 도구를 설치하지 않고 명세, 설계, 작업 분해, 구현, 브라우저 확인, 변경 영향을 따라 합니다 | 윤성열 |
| [M07 — 양식으로 명세를 쓰고 요구에서 테스트까지 추적하기](M07-spec-template-and-trace/) | 기능 하나(할 일 생성)의 요구를 빈 양식에 채워 명세로 만들고, 작은 사례에서 요구가 테스트까지 이어지는지 따라갑니다 | 윤성열 |

M01~M05는 도구별 가이드입니다. M06과 M07은 이 가이드들을 대신하지 않습니다. SDD 도구를 설치하지 않고 Claude Code와 일반 파일 작업으로 판단 과정을 연습하는 단원입니다.
