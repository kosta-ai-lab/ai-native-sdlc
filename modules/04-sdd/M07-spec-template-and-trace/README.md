# 모듈 04 · 단원 M07 — 양식으로 명세를 쓰고 요구에서 테스트까지 추적하기

> 상태: 초안 · 담당: 윤성열 · 예제: 할 일 생성(함수 하나)
> 검증 기준: Claude Code 2.1.330(모델 Sonnet 5.5) · Node.js v24.22.0 · pnpm 12.21.0 · 2026-11-24

## 목적

요구사항이 “제목이 있는 할 일을 생성할 수 있다”라면 명세는 입력 형태, 반환값, 초기 상태, 오류 조건을 정해 구현하는 사람과 테스트를 쓰는 사람이 같은 결과를 예상하게 합니다. 이 단원은 요구 세 개(R-01~R-03)를 빈 양식에 채워 명세로 만들고, 완성된 작은 사례에서 요구가 테스트까지 이어지는지 직접 따라갑니다.

이 단원의 뼈대는 이 과정의 네 가지 원칙입니다. ① AI는 제안하고, 결정은 사람이 한다. ② 말이 아니라 실행 결과로 확인한다. ③ 맡길수록 절차가 필요하다. ④ 앞 단계가 뒤 단계의 기준이다. 그래서 GUIDE의 단계를 **맡긴다 → 확인한다 → 정한다 → 넘긴다**의 네 마디로 나눴습니다.

이 단원을 마치면 다음을 할 수 있습니다.

- 요구·UC·결정·미결을 읽고 모델과 동작 계약으로 구체화한다.
- 요구가 정한 것과 사람이 고른 기술 선택, AI의 제안을 구별해 기록한다.
- 요구 → 명세 → 인수조건 → 테스트의 대응을 찾고, 없는 것과 실행하지 않은 것을 표시한다.
- 변경 요청을 반영하기 전에 명세와 뒤 단계에 주는 영향을 목록으로 만든다.

| 실습 | 명세 양식 채우기, 기술 선택에 답하기, 예제와 비교, 요구에서 테스트까지 따라가기, 변경 영향, 인계 |

## 사전 준비물

- 이 강의 자료 저장소의 사본. 0단계와 4단계의 명령을 저장소 루트 폴더에서 실행합니다.
- Claude Code. 설치와 로그인을 마친 상태여야 합니다. `claude --version`으로 확인합니다. 설치 방법은 Claude Code 공식 문서(https://code.claude.com/docs)를 따릅니다.
- git과 Markdown 편집기.
- Node.js와 pnpm. 4단계에서 작은 사례의 테스트를 실행할 때 씁니다. `node --version`, `pnpm --version`으로 확인합니다.

## 완료 기준

- [ ] 요구 ID마다 명세 규칙이 있고, 정상 입력과 거부 입력의 결과를 명세만 읽고 말할 수 있다.
- [ ] 기술 선택마다 결정 주체와 이유가 있고, 내가 정하지 않은 것은 제안이나 미결로 남아 있다.
- [ ] 작은 사례에서 R-01~R-03이 이어지는 시나리오와 테스트 단언을 찾았다.
- [ ] 변경 요청의 영향 목록이 있고, 승인 전에는 명세 본문을 고치지 않았다.

## 검증 기록 (2026-11-24)

- 환경: macOS, Claude Code 2.1.330(모델 Sonnet 5.5), Node.js v24.22.0, pnpm 12.21.0, Vitest 3.2.6, git 2.56.1
- GUIDE 1·2·4·5단계의 요청을 Claude Code 비대화형 모드(`claude -p`)로 두 번씩 실행했고, 4단계의 요청은 한 번 더 실행했습니다. 합계 9회입니다. 요청마다 새 세션이고 요청 사이에는 파일만 이어졌습니다.
- 설정 파일은 프로젝트 것만 읽게 했고(`--setting-sources project,local`), 사용자 전역 지침 파일은 읽지 않게 했습니다(`claudeMdExcludes` 설정). 권한 모드는 파일 편집을 자동으로 허용하는 모드(`acceptEdits`)였습니다. Claude가 실행하려다 거부된 것은 2단계의 `python3` 스크립트, 4단계의 `node`와 `npx vitest` 실행, 폴더 밖 임시 파일 쓰기입니다.
- 4단계의 요청 가운데 처음 두 번은 사본을 복사한 직후, 설치하기 전에 실행했습니다. 설치, 테스트, 타입 검사는 그 뒤에 같은 사본에서 직접 실행했습니다. 테스트 2개가 통과했고 타입 검사는 종료 코드 0이었습니다. 세 번째 요청은 설치를 마친 사본에서 `pnpm test`를 허용하고 실행했습니다.
- 확인한 것은 다음과 같습니다. 결과는 GUIDE 각 단계의 ‘검증 실행에서 본 것’에 적었습니다.
  - 단계마다 어떤 파일이 바뀌는지와 양식의 구성이 유지되는지
  - 요구에 없는 기술 선택이 제안으로 구분되는지
  - 없는 파일과 실행하지 않은 검사를 있는 것처럼 적는지
  - 답하지 않은 질문이 미결로 남는지
  - 변경 요청에서 명세 본문을 고치는지
- 한계: 실행 횟수가 적고 모델과 버전이 하나입니다. 다른 운영체제, 대화형 화면에서의 표시, 한 세션에서 이어서 진행하는 경우는 확인하지 않았습니다. 3단계와 6단계는 사람이 하는 단계라 AI 실행으로 검증하지 않았습니다. 명령은 macOS 터미널 기준입니다.
- [SAMPLE.md](SAMPLE.md)는 수업용으로 만든 예제이며 이 검증 실행의 출력이 아닙니다. 실제 프로젝트의 승인 기록도 아닙니다.
