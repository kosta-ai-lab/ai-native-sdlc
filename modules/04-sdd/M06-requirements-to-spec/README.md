# 모듈 04 · 단원 M06 — 요구사항에서 명세·설계·구현 검증으로

> 상태: 초안 · 담당: 윤성열 · 예제: 개인용 할 일 관리 웹 앱
> 검증 기준: Claude Code 2.1.330(모델 Sonnet 5.5) · Node.js v24.22.0 · Python 3.15.2 · 2026-11-24

## 목적

요구사항에 ‘목록이 남아 있어야 한다’라고 적혀 있어도 구현자는 무엇을 언제 저장하고, 저장이 실패하면 화면을 어떻게 할지 결정해야 합니다. 이 단원은 **요구사항을 모델·행위·제약으로 구체화하고, 설계와 작업 분해를 거쳐 실행 결과로 되돌아오는 SDD 실습**입니다. 문서가 생겼다는 이유만으로 끝났다고 보지 않습니다.

이 단원의 뼈대는 이 과정의 네 가지 원칙입니다. ① AI는 제안하고, 결정은 사람이 한다. ② 말이 아니라 실행 결과로 확인한다. ③ 맡길수록 절차가 필요하다. ④ 앞 단계가 뒤 단계의 기준이다. 그래서 GUIDE의 단계를 **맡긴다 → 확인한다 → 정한다 → 넘긴다**의 네 마디로 나눴습니다.

이 단원을 마치면 다음을 할 수 있습니다.

- 요구·명세·설계의 관계를 설명하고 사용자 목적을 구현 조건으로 연결한다.
- 데이터 모델, 정상·실패 행위, 지켜야 할 제약을 일관되게 정한다.
- 설계에서 테스트와 구현 작업을 도출하고 요구→작업→실제 확인을 추적한다.
- 변경을 명세와 설계·코드·검증에 함께 반영한다.

## 검증 기록 (2026-11-24)

- 환경: macOS, Claude Code 2.1.330(모델 Sonnet 5.5), Node.js v24.22.0, Python 3.15.2, git 2.56.1, Chromium
- GUIDE의 요청을 Claude Code 비대화형 모드(`claude -p`)로 실행했습니다. 1~3단계는 두 번씩, 4단계는 한 번의 흐름에서 일곱 번, 6단계는 두 번입니다. 합계 15회입니다. 요청마다 새 세션이고 요청 사이에는 파일만 이어졌습니다.
- 설정 파일은 프로젝트 것만 읽게 했고(`--setting-sources project,local`), 사용자 전역 지침 파일은 읽지 않게 했습니다(`claudeMdExcludes` 설정). 권한 모드는 파일 편집을 자동으로 허용하는 모드(`acceptEdits`)였고, 따로 허용한 명령은 `node --test`, `ls`, `git status`, `git diff`입니다. 4단계에서 `npm test`, `npm start`, `curl`은 거부됐습니다.
- 5단계는 사람이 하는 단계입니다. 4단계에서 만들어진 앱을 로컬 서버로 띄우고, 브라우저 자동화 도구로 Chromium을 조작해 SAMPLE 6장의 1~9번, 길이 경계, 7장의 두 가지 실패를 확인했습니다. 7번은 새로 고침만 확인했습니다. 8번에서 결함 하나를 찾았고 GUIDE 5단계에 적었습니다. 독립 검토자가 같은 앱을 따로 띄워 같은 결과를 다시 확인했습니다.
- 인용한 내용은 IREB의 CPRE 온라인 용어집, GitHub Spec Kit의 `spec-driven.md`, NPR 7150.2D 원문과 대조했습니다.
- 한계는 다음과 같습니다.
  - 구현까지 간 흐름은 하나입니다. 다른 실행에서는 파일 구성도, 나오는 결함도 다를 수 있습니다.
  - 찾은 결함을 고치는 과정과, 6단계의 변경을 실제로 반영하고 다시 검증하는 과정은 실행하지 않았습니다.
  - 대화형 화면에서의 표시, 한 세션에서 이어서 진행하는 경우, 다른 운영체제는 확인하지 않았습니다. 0단계의 명령은 macOS 터미널 기준입니다.
- [SAMPLE.md](SAMPLE.md)의 명세·설계·작업 예는 수업용 비교 예문이며 이 검증 실행의 출력이 아닙니다.

## 기존 자료를 재사용하는 방법

이 단원은 새 도구를 설치하는 대신 **일반 파일 작업으로 SDD의 판단 과정을 먼저 연습**합니다. 이미 [Kiro M01](../M01-kiro/README.md)이나 [Spec Kit M03](../M03-spec-kit/README.md)으로 같은 범위의 앱을 만들었다면 다시 개발하지 말고 그 프로젝트의 명세·설계·작업·테스트를 이 실습 기준으로 대조합니다. 도구 특유의 설치·명령·자동화는 해당 가이드를 따릅니다. 각 도구를 모두 설치하는 것은 이 단원의 요구가 아닙니다.

[할 일 생성 샘플](../../../samples/web-task-system/README.md)은 요구에서 테스트로 이어지는 작은 실행 자료입니다. 웹 앱 전체를 제공하는 샘플은 아닙니다. SAMPLE의 웹 앱 절차는 **수강생이 만들고 고친 앱을 검증하는 절차**입니다.
