# 모듈 — Jev 드론 1 — 직접 만든 2D 드론 시뮬레이터

> 상태: 초안 · 담당: 이선아 교수

## 목적

바람·배터리·장애물·지오펜스가 있는 **간단한 2D 드론 시뮬레이터**를 순수 Python으로 직접 만들고, 그 위에서 **배달 임무**(이륙 → 경유지 방문 → 복귀 → 착륙)를 수행하는 드론 에이전트를 만든다. 핵심은 세 가지다.

1. **3계층 구조**: Jev 판단 계층 + 안전 감시 계층 + PID 제어 계층
2. **임무 단계 판단**: 이륙·이동·회피·복귀·착륙 중 "지금 어느 단계여야 하는가"를 Jev가 판단
3. **평가 하네스**: 같은 시나리오·같은 시드로 여러 두뇌를 돌려 **성공률·충돌·지연·비용**을 한 표로 비교

M07(실시간 게임)의 판단 관리자(비동기·예산·유지·신뢰도)를 그대로 가져오고, 세계를 "게임"에서 "드론 시뮬레이터"로 바꾼다. 이 모듈의 계층 구조와 평가 하네스는 다음 모듈(PX4 + Gazebo 시뮬레이터)에서도 그대로 쓴다.

> 선수 모듈: [M07-realtime-agent](../M07-realtime-agent/README.md) (세 가지 주기, 비동기 호출, 지연 시간 예산, 신뢰도 기반 안전 행동)

```
│ ↗ 바람        ⬤ 장애물(회색)     ◯ 비행 금지 구역(붉은 반투명)                       ││ ■■■■■□ 62.3%   │

│  [H] 집 (이륙·착륙 지점)                                                         ││ home needs 4.1%│

```

## 3계층 구조

```
            5Hz (느림, 0.2~0.5초 걸림)                  60Hz                         60Hz
 ┌──────────────────────────┐   단계 + 방향   ┌──────────────────────┐  방향   ┌──────────────────────┐ 추력  ┌─────────┐
 │ ① 판단 계층 (Jev 또는 규칙)  │ ─────────────▶ │ ② 안전 감시 계층         │ ──────▶ │ ③ 제어 계층 (PID)      │ ────▶ │ 시뮬레이터 │
 │ "계속 갈까, 돌아갈까,        │  TRANSIT, NE    │ 장애물 → 비켜남           │         │ 방향 → 목표 속도        │       │ 바람·배터리 │
 │  어느 쪽으로?"              │                 │ 지오펜스·금지 구역 → 멈춤  │         │ 목표 속도 → 추력 (PID)  │       │ 충돌·센서  │
 └──────────────────────────┘                 │ 배터리 → 강제 복귀·착륙    │         │ 목표 고도 → 상승 속도    │       └─────────┘
            ▲                                  └──────────────────────┘         └──────────────────────┘
            └──── 관측: 배터리·필요 배터리 예상·목표·바람·8방향 거리 센서·금지 구역·지오펜스 여유 ────┘
```

| 계층 | 파일 | 주기 | 하는 일 | 실제 드론에서 |
|---|---|---|---|---|
| ① 판단 | `brains.py`, `decider.py` | 5Hz | 임무 단계와 비행 방향 선택 | 동반 컴퓨터(companion computer)의 임무 판단 |
| ② 안전 감시 | `safety.py` | 60Hz | 위험하면 비켜나기·멈추기·강제 복귀·강제 착륙 | 비행 컨트롤러의 충돌 방지·지오펜스·배터리 페일세이프 |
| ③ 제어 | `pid.py`, `mission.py` | 60Hz | 방향 → 목표 속도 → PID → 추력 | 비행 컨트롤러(PX4 등)의 속도·고도 제어 |
| 시뮬레이터 | `physics.py` | 60Hz | 바람, 배터리, 관성, 충돌, 센서 | Gazebo 같은 물리 시뮬레이터 또는 실제 세상 |

**왜 세 계층으로 나누나?** 각 계층은 잘하는 일이 다르다.

| 계층 | 잘하는 것 | 못하는 것 |
|---|---|---|
| 판단 (Jev) | 여러 정보를 종합한 판단 ("배터리, 바람, 남은 경유지를 보면 지금 돌아가야 한다") | 빠른 반응 (0.2초 이상 걸림), 100% 보장 |
| 안전 감시 (규칙) | 절대 넘으면 안 되는 선을 60Hz로 확실히 지킴 | 임무 판단 (멈추게만 할 뿐 어디로 가야 할지 모름) |
| 제어 (PID) | 바람 속에서도 목표 속도를 정확히 유지 | 어디로 갈지는 모름 |

## 임무 단계

```
 TAKEOFF ──▶ TRANSIT ⇄ AVOID ──▶ RETURN (⇄ AVOID) ──▶ LAND ──▶ LANDED
   이륙         이동      회피        복귀                  착륙      완료
                  └─────────────▶ RETURN (임무 포기: 배터리·위험)
```

| 전환 | 누가 결정 | 이유 |
|---|---|---|
| TAKEOFF → TRANSIT (고도 도달) | 코드 | 정확한 기계적 조건 |
| 경유지 도착 → 다음 경유지, 모두 끝나면 RETURN | 코드 | 정확한 기계적 조건 |
| **TRANSIT ⇄ AVOID** (회피할지) | **두뇌 (Jev)** | 장애물·금지 구역·바람을 종합한 판단 |
| **TRANSIT → RETURN** (임무 포기) | **두뇌 (Jev)** | 배터리 예상·바람·남은 경유지를 종합한 판단. 되돌릴 수 없음 |
| 집 도착 → LAND, 착지 → LANDED | 코드 | 정확한 기계적 조건 |
| 강제 RETURN / 강제 LAND | **안전 감시** | 배터리가 정말 위험할 때 |

M03에서 배운 원칙 그대로, **계산할 수 있는 것은 코드가 계산해서 관측에 넣는다** (집까지 필요한 배터리 %, 임무를 끝내는 데 필요한 배터리 %). Jev는 그 숫자들과 바람·위험을 종합해 **판단**한다. Jev에게 묻는 질문은 두 개이고, 한 번의 호출로 병렬로 평가된다.

| 질문 | 종류 | 선택지 |
|---|---|---|
| `phase` | Choice | 지금 허용된 단계만 (이동 중: TRANSIT / AVOID / RETURN, 복귀 중: RETURN / AVOID) |
| `heading` | Choice | 위험하지 않은 방향만 + HOVER (행동 마스킹) |

## 시뮬레이터에 들어 있는 것

| 요소 | 모델 | 왜 중요한가 |
|---|---|---|
| **바람** | 평균 바람 + 돌풍(몇 초에 걸쳐 천천히 변하는 무작위). 공기 저항으로 드론을 밀어냄 | P 제어만으로는 떠밀림 → PID의 I항이 필요 |
| **배터리** | 떠 있기만 해도 0.35%/초, 공기 대비 속도² 에 비례해 추가 소모 (맞바람이면 더 듦) | 언제 임무를 포기하고 돌아올지 판단해야 함 |
| **장애물** | 원기둥. 부딪히면 충돌 | 회피 판단, 안전 감시 |
| **지오펜스** | 30m × 20m 사각형, 경계 1m 안쪽까지만 | 규칙상 절대 넘으면 안 되는 선 |
| **비행 금지 구역** | 원. 부딪히지는 않지만 들어가면 위반 | "물리적으로 가능하지만 하면 안 되는 것" |
| **거리 센서** | 8방향, 장애물까지 거리 (최대 6m) | 판단 계층의 관측 |
| **관성·고도** | 최대 가속 5m/s², 순항 고도 3m, 상승·하강 1.5m/s | 바로 멈추지 못함, 이륙·착륙에 시간이 걸림 |

## 평가 하네스

임무 하나의 성공·실패는 운에 좌우된다 (돌풍, 지연). 그래서 **같은 시나리오 × 같은 시드**로 여러 두뇌를 돌리고 같은 지표로 비교한다.

| 지표 | 정의 | 왜 |
|---|---|---|
| **완수율** | 모든 경유지 방문 + 무사고 귀환 비율 | 임무를 해냈는가 |
| **무사고 귀환율** | 충돌·위반 없이, 예비 배터리(8%)를 남기고 집에 착륙한 비율 | 다 못 하는 임무에서는 "포기하고 무사히 돌아오기"가 정답 |
| 충돌, 위반 | 평균 장애물 충돌, 지오펜스·금지 구역 위반 횟수 | 안전 |
| 시간, 배터리 | 평균 비행 시간, 평균 남은 배터리 | 효율 |
| 안전 감시 개입 | 안전 계층이 판단을 덮어쓴 횟수 | 판단 계층이 상황을 잘 보는가 |
| **지연 p95** | 판단 응답 시간의 95번째 백분위수 | 평균보다 "가끔 크게 늦는 것"이 위험 |
| **호출, 비용** | 판단 요청 수, Jev 입력 토큰 × 단가 ($0.042/100만 토큰, 출력 무료) | 운영 비용 |

결과는 `reports/`에 JSON과 CSV로 저장되어, 설정을 바꾸기 전과 후를 비교할 수 있다.

## 품질 기준

동작하는 샘플 또는 재현 가능한 프롬프트가 반드시 첨부되어야 하며, 문서는 따라 하면 되는 수준이어야 한다.

> **검증 상태:** 시뮬레이터, PID 비교, 규칙 두뇌, 안전 감시, 평가 하네스(Jev 제외)는 실제로 실행했고 GUIDE.md에 실린 표는 실제 출력이다. pygame 화면은 화면 없는 환경(SDL dummy 드라이버)에서 실행해 동작을 확인했다. Jev 두뇌는 실제 API 키 없이 **SDK 모양·지연·토큰 사용량을 흉내 낸 테스트용 가짜 모듈**로 두 질문(단계·방향), 비동기 호출, 로그, 비용 계산 경로를 확인했다. Jev의 실제 판단 결과·지연·비용은 수업 전에 키로 실행해 GUIDE.md를 갱신할 것.

## 기준 버전

- 모델: `jev-latest`
- SDK: `typesafe-sdk` (Python), 문서 확인일 2026-11-25
- 화면: `pygame-ce` 2.5 (Python 3.14에서 확인)
- 비용 단가: 입력 100만 토큰당 $0.042, 출력 무료 (TypeSafe 블로그 발표 기준, 바뀔 수 있음)
