# 모듈 — Jev 게임 에이전트 1 — 격자 게임으로 배우는 결정 루프

> 상태: 초안 · 담당: 이선아 교수

## 목적

격자(grid) 위의 "드론"을 목표 지점까지 보내는 턴제 게임을 만들고, **Jev가 매 턴 다음 행동을 고르는 게임 에이전트**를 만든다. 이 과정에서 드론 제어까지 그대로 이어지는 세 가지를 익힌다.

1. **결정 루프**: 관측 → state → Jev 판단 → 안전 감시 → 행동을 반복하는 구조
2. **state 설계**: 게임 상황을 Jev가 판단하기 좋은 JSON으로 바꾸는 법
3. **판단과 안전의 분리**: Jev가 무엇을 고르든 위험한 행동은 규칙 코드가 막는 구조

> 선수 모듈: [M01-basics](../M01-basics/README.md) (Choice·Noul, 확률로 분기하기)

## 왜 격자 게임인가

| 이유 | 설명 |
|---|---|
| state가 작다 | `{"drone": {"x":1,"y":1}, "target": {"x":4,"y":3}}`만으로 시작할 수 있다 |
| 행동이 4개뿐이다 | `up` / `down` / `left` / `right` → Choice 질문 하나로 끝난다 |
| 채점이 쉽다 | 목표에 가까워졌는지, 벽에 부딪혔는지 코드로 바로 알 수 있다 |
| 드론 비행과 구조가 같다 | "현재 위치와 목표를 보고 다음 이동을 고른다" = 웨이포인트 비행 |
| 난이도를 조금씩 올릴 수 있다 | 빈 격자 → 벽 → 함정 → 배터리·바람 |

틱택토처럼 몇 수 앞을 읽어야 하는 게임은 빠른 판단(System 1)에 특화된 Jev에게 맞지 않는다. 격자 게임은 **"지금 보이는 상황에서 다음 한 수"**를 고르는 문제라 Jev의 성격과 잘 맞는다.

## 핵심 개념 5가지

### 1. 결정 루프 (Decision Loop)
게임 에이전트와 드론 제어기는 모두 같은 루프를 돈다.

```
① 관측 → ② state 만들기 → ③ 판단(Jev) → ④ 안전 감시 → ⑤ 행동 → 다시 ①
 게임 상태   JSON으로 정리     다음 행동 고르기   위험하면 교체     한 칸 이동
```

이 모듈의 [runner.py](grid-agent/runner.py)가 이 루프이고, 다음 모듈들(실시간 게임, 드론 시뮬레이터)에서도 같은 모양을 유지한다.

### 2. State 설계 — Jev가 보는 세상
Jev는 **state에 넣어 준 것만** 보고 판단한다. 같은 Jev라도 state를 어떻게 만드느냐에 따라 결과가 크게 달라진다.

| state 항목 | 넣으면 좋아지는 것 | 실습 단계 |
|---|---|---|
| `drone`, `target` 좌표 | 기본 방향 판단 | 4단계 |
| `coordinate_system` | "up이 y를 줄인다" 같은 약속을 명확히 함 | 4단계 |
| `neighbors` (상하좌우 칸: free/wall/edge) | 벽에 부딪히지 않기 | 5단계 |
| `map` (지도 글자 그림) | 벽을 돌아가는 길 찾기 | 5단계 |
| `recent_moves` (최근 행동 4개) | 같은 자리 왕복 줄이기 | 4단계부터 |
| `battery`, `steps_to_home` 등 계산된 값 | 복귀 판단 | 6단계 |

**계산할 수 있는 것은 코드가 계산해서 넣어 준다**는 것이 핵심이다. 예를 들어 "집까지 몇 걸음"은 코드가 정확히 계산할 수 있으므로 Jev에게 지도를 보고 세게 하지 않고 숫자로 준다. Jev는 그 숫자들을 종합해 **판단**하는 데 집중한다.

### 3. 행동 공간 (Action Space) = Choice 질문
에이전트가 할 수 있는 행동 목록을 그대로 Choice의 선택지로 만든다. Jev는 선택지 밖의 답을 내지 않으므로 **"알 수 없는 명령"이 나올 일이 없다**. 드론에서는 이 선택지가 `goto`, `hold`, `land`, `return_home` 같은 고수준 명령이 된다.

### 4. 판단과 안전 감시의 분리
Jev의 답은 확률적이다. 그래서 **절대 일어나면 안 되는 일**은 Jev에게 맡기지 않고 [safety.py](grid-agent/safety.py)가 막는다.

| 안전 규칙 | 게임에서 | 드론에서 |
|---|---|---|
| 막힌 칸으로 이동 금지 | 벽·격자 밖 이동을 막고, **갈 수 있는 행동 중 Jev 확률이 가장 높은 것**으로 교체 | 지오펜스, 장애물 회피 |
| 배터리 강제 복귀 | 남은 배터리 ≤ 집까지 거리 + 여유분이면 무조건 복귀 | RTL (Return To Launch) |

Jev가 확률을 함께 주기 때문에, 1순위가 막혔을 때 **2순위로 자연스럽게 넘어갈 수 있다**는 점이 LLM과 다른 장점이다.

### 5. 기준 에이전트와 비교 평가
Jev가 잘하는지 알려면 **비교 기준**이 있어야 한다. 이 모듈은 "목표와의 거리가 줄어드는 방향으로 간다"는 단순 규칙 에이전트를 기준으로 삼는다. 이 규칙은 빈 격자와 벽이 적은 지도에서는 완벽하지만, **함정 지도에서는 막혀서 제자리를 맴돈다**. Jev가 지도를 보고 돌아가는 길을 찾는지, 어떤 state를 줘야 찾는지가 이 모듈의 핵심 실험이다.

## 게임 → 드론 대응표

| 이 모듈 (격자 게임) | 드론 제어 |
|---|---|
| 격자 한 칸 이동 | 웨이포인트 하나 이동 |
| `up/down/left/right` Choice | `goto`, `hold`, `land`, `return_home` 같은 고수준 명령 |
| 벽, 격자 밖 | 장애물, 비행 금지 구역(지오펜스) |
| 배터리, 맞바람 | 실제 배터리 소모, 바람 |
| `return_home` Noul | 임무 중단·복귀 판단 |
| `SafetyFilter` | 비행 컨트롤러의 페일세이프 |
| 턴마다 한 번 판단 | 2~5Hz 주기 판단 (M07에서 실시간으로 바꿈) |

└── logs/              # 실행하면 생기는 결정 기록 (JSONL)

## 품질 기준

동작하는 샘플 또는 재현 가능한 프롬프트가 반드시 첨부되어야 하며, 문서는 따라 하면 되는 수준이어야 한다.

> **검증 상태:** 게임·규칙 에이전트·안전 감시·비교표는 실제로 실행해 결과를 확인했다 (GUIDE.md의 규칙 에이전트 결과는 실제 출력). Jev 에이전트는 실제 API 키 없이 **SDK 모양만 흉내 낸 테스트용 가짜 모듈**로 코드 경로만 확인했다. Jev의 실제 판단 결과는 수업 전에 키로 실행해 GUIDE.md의 예시를 갱신할 것.
