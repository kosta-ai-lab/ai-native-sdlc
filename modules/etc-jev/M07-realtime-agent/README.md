# 모듈 — Jev 게임 에이전트 3 — 실시간 드론 게임 (2D 장애물 회피·목표 수집)

> 상태: 초안 · 담당: 이선아 교수

## 목적

M03·M05의 게임은 **턴제**라서 Jev가 답할 때까지 세계가 기다려 줬다. 실제 드론은 기다려 주지 않는다. 이 모듈에서는 pygame으로 만든 **실시간 2D 드론 게임**(장애물을 피해 목표물 5개 수집)에서, 응답에 0.2~0.5초가 걸리는 두뇌(Jev)로 1초에 60번 움직이는 드론을 안전하게 조종하는 방법을 배운다.

다루는 것:

1. **판단 주기와 화면·물리 주기 분리** — 물리 60Hz, 화면 60FPS, 판단 5Hz
2. **비동기 호출** — 두뇌가 생각하는 동안에도 세계·화면·안전 감시는 계속 돈다
3. **지연 시간 예산** — 너무 늦게 도착한 답은 "이미 지난 상황"이므로 버린다
4. **응답이 늦을 때 이전 행동 유지**, 너무 오래 늦으면 **안전 행동(HOVER)**
5. **신뢰도가 낮으면 안전 행동** — Jev의 확률을 이용
6. **60Hz 안전 감시** — 관성(멈추는 거리)까지 고려한 마지막 방어선

이 게임은 처음부터 **드론 시뮬레이터([M09](../M09-drone-sim/README.md))로 그대로 옮길 수 있게** 설계했다. 단위는 미터·초이고, 두뇌는 "북동쪽으로" 같은 고수준 명령만 내며, 그 명령을 속도로 바꾸는 저수준 제어기(비행 컨트롤러 역할)와 안전 감시가 따로 있다.

> 선수 모듈: [M05-maze-escape](../M05-maze-escape/README.md) (관측 설계, 행동 마스킹, 확률 기반 대체)

## 핵심 구조: 세 계층 × 세 주기

```
 ┌───────────────┐  5Hz, 0.2~0.5초 걸림    ┌──────────────┐  60Hz    ┌───────────────┐  60Hz   ┌──────────┐
 │ 두뇌 (Brain)   │ ─── 고수준 명령 ───────▶ │ 판단 관리자    │ ───────▶ │ 안전 감시       │ ──────▶ │ 제어기     │ ──▶ 드론
 │ 규칙 / Jev     │   "NE", "HOVER" ...     │ (Decider)     │ 지금 명령 │ (SafetyFilter) │ 최종명령 │ 명령→속도  │
 └───────────────┘                         │ 예산·유지·신뢰도 │          │ 관성까지 고려    │         └──────────┘
        ▲                                  └──────────────┘          └───────────────┘
        └──────── 관측 복사본 (snapshot): 8방향 거리 센서, 목표 위치, 주변 장애물 ────────┘
```

| 계층 | 파일 | 주기 | 하는 일 | 드론에서 |
|---|---|---|---|---|
| 두뇌 | `brains.py` | 5Hz (느림) | 상황을 보고 고수준 명령 선택 | 동반 컴퓨터(companion computer)의 임무 판단 |
| 판단 관리자 | `decider.py` | 60Hz | 비동기 요청, 예산, 유지, 신뢰도 처리 | 동반 컴퓨터의 제어 노드 |
| 안전 감시 | `safety.py` | 60Hz | 충돌 직전이면 정지 | 비행 컨트롤러의 충돌 방지·지오펜스 |
| 제어기 | `controller.py` | 60Hz | 명령 → 목표 속도 → 실제 속도 | 비행 컨트롤러(PX4 등)의 속도 제어 |
| 세계 | `world.py` | 60Hz | 물리, 센서, 충돌 | 시뮬레이터(Gazebo) 또는 실제 세상 |

## 핵심 개념 6가지

### 1. 세 가지 주기 분리
| 주기 | 값 | 이유 |
|---|---|---|
| 물리·제어 | 60Hz | 드론은 연속적으로 움직이고, 제어기는 자주 고칠수록 안정적 |
| 화면 | 60FPS | 사람이 부드럽게 보도록 |
| **판단** | **5Hz** | Jev 응답이 0.2~0.5초 걸리고, 호출마다 비용이 들기 때문 |

판단을 물리처럼 60Hz로 하면 호출이 12배 늘지만 결과는 거의 같다 (실측: 5Hz와 20Hz의 완료 시간 차이 0.2초, 호출 수는 4배). **판단 주기는 "응답 시간보다 길고, 상황이 바뀌는 속도보다 짧게"** 정한다.

### 2. 동기 vs 비동기 호출
| 방식 | 기다리는 동안 | 결과 (실측, 지연 0.3초) |
|---|---|---|
| **동기 (sync)** | 프로그램 전체가 멈춤. 화면도, 안전 감시도 멈추지만 **드론은 계속 날아감** | 화면 18FPS, 충돌 많음 |
| **비동기 (async)** | 두뇌는 다른 스레드에서 생각하고, 나머지는 60Hz로 계속 | 화면 61FPS, 안전 감시가 계속 작동 |

동기 호출의 진짜 위험은 화면이 끊기는 것이 아니라 **기다리는 동안 안전 감시가 눈을 감는다**는 것이다.

### 3. 지연 시간 예산 (Latency Budget)
요청을 보낸 순간의 관측으로 만든 답은, 도착했을 때 이미 과거의 답이다. 0.3초면 드론은 이미 0.6m를 날아갔다. **예산(예: 0.6초)보다 늦게 도착한 답은 버린다.**

### 4. 이전 행동 유지 (Hold)와 시간 초과 안전 행동
새 답이 아직 없으면 **이전 명령을 유지**한다 (드론은 계속 명령이 필요하다). 하지만 **너무 오래(예: 0.8초) 새 답이 없으면 HOVER**로 바꾼다. 오래된 명령으로 계속 나는 것은 눈 감고 나는 것과 같다.

> 실측 교훈 (30판 평균): 예산만 쓰면 효과가 작다 (충돌 1.4 → 1.3). 늦은 답을 버려도 그동안 이전 명령으로 계속 날기 때문이다. 유지 한도까지 쓰면 충돌 1.0, 안전 감시 개입은 절반으로 줄지만, 멈춰 기다리는 만큼 느려진다. **예산과 유지 한도는 함께** 쓰고, 안전과 속도의 균형을 실측으로 정한다.

### 5. 신뢰도가 낮으면 안전 행동
Jev는 답과 함께 확률을 준다. 고른 명령의 확률이 기준(예: 0.55)보다 낮으면 **HOVER**한다. M05에서는 애매할 때 "규칙에게" 넘겼다면, 실시간에서는 "일단 멈추고 다음 판단을 기다린다". 기준이 너무 높으면(예: 0.9) 드론이 거의 움직이지 못한다.

### 6. 60Hz 안전 감시와 관성
드론은 명령을 바꿔도 바로 멈추지 못한다 (최대 가속도 4m/s², 2m/s에서 멈추는 데 0.5m). 안전 감시는 **가려는 방향**뿐 아니라 **지금 날아가는 방향의 멈춤 거리**까지 매 주기 확인한다. 두뇌가 5Hz로 놓친 위험을 60Hz로 잡는 마지막 방어선이다.

## 이 모듈의 흐름 (GUIDE.md 1~7단계)

| 단계 | 파일 | 두뇌 | 배우는 것 | API 키 |
|---|---|---|---|---|
| 1 | `00_play_manual.py` | 사람 | 미터 단위 세계, 관성, 센서, 안전 감시 | 필요 없음 |
| 2 | `01_rule_brain.py` | 규칙 | 세 가지 주기, 판단 주기 바꾸기 | 필요 없음 |
| 3 | `02_latency_sync.py` | 규칙 + 지연 흉내 | 동기 vs 비동기 | 필요 없음 |
| 4 | `03_latency_policies.py` | 규칙 + 지연 흉내 | 지연 시간 예산, 이전 행동 유지, 시간 초과 | 필요 없음 |
| 5 | `04_jev_brain.py` | **Jev** | 실제 지연에서 비동기·예산·유지 적용 | 필요 |
| 6 | `05_low_confidence.py`, `04_jev_brain.py --min-prob` | 흉내 → **Jev** | 신뢰도 낮으면 안전 행동 | 일부 필요 |
| 7 | `06_compare.py` | 규칙 vs Jev | 종합 비교, 드론 시뮬레이터로 옮길 준비 | 일부 필요 |

1~4단계와 6단계 앞부분은 API 키 없이 진행할 수 있다. 네트워크 지연과 "확률을 말하는 모델"을 흉내 낸 두뇌(`LatencyModel`, `NoisyBrain`)로 먼저 개념을 익힌 뒤, 같은 코드에 Jev를 꽂는다.

## 드론 시뮬레이터로 옮길 때의 대응표

이 모듈의 코드는 거의 그대로 드론 시뮬레이터로 옮겨진다. **바뀌는 것은 세계와 제어기뿐**이고, 두뇌·판단 관리자·안전 감시의 구조는 유지된다. 먼저 [M09](../M09-drone-sim/README.md)에서 `world.py`를 바람·배터리·지오펜스가 있는 **직접 만든 2D 드론 시뮬레이터**로, `controller.py`를 **PID**로 바꾸고, 그다음 M11에서 아래 표처럼 실제 비행 스택(PX4)으로 옮긴다.

| 이 모듈 | 드론 시뮬레이터 / 실제 드론 | 비고 |
|---|---|---|
| `world.py` (2D 물리) | Gazebo + PX4 SITL (3D 물리) | 세계를 통째로 교체 |
| `controller.py` (명령 → 속도) | PX4 속도 제어 + MAVSDK offboard 속도 명령 | "NE" → 북동쪽 속도 명령 |
| 좌표 x=동, y=북 | NED 좌표 (x=북, y=동, z=아래) | 축 순서가 바뀌므로 주의 |
| `world.rays()` 8방향 거리 | 거리 센서·깊이 카메라 | 관측 형태 유지 |
| `world.snapshot()` | 텔레메트리(위치·속도) + 센서 값 | 두뇌가 받는 것은 같음 |
| `decider.py` (60Hz 명령 유지) | offboard 명령을 **끊임없이 계속 보내야** 하는 규칙 | PX4는 offboard 명령이 끊기면 페일세이프에 들어감. "이전 명령 유지"가 그대로 필요 |
| `HOVER` | 속도 0 명령 또는 Hold 모드 | 안전 행동 |
| `safety.py` | PX4 충돌 방지 + 지오펜스 + 동반 컴퓨터의 추가 감시 | 두 겹으로 |
| 판단 5Hz, 예산 0.6초, 유지 0.8초 | 같은 값에서 시작해 실측으로 조정 | 7단계 결과를 근거로 |

## 품질 기준

동작하는 샘플 또는 재현 가능한 프롬프트가 반드시 첨부되어야 하며, 문서는 따라 하면 되는 수준이어야 한다.

> **검증 상태:** 게임, 규칙 두뇌, 지연 흉내, 흉내 모델(NoisyBrain), 비교표는 실제로 실행했고 GUIDE.md에 실린 표는 실제 출력이다. pygame 화면은 화면 없는 환경(SDL dummy 드라이버)에서 실행해 FPS와 동작을 확인했다. Jev 두뇌는 실제 API 키 없이 **SDK 모양과 지연만 흉내 낸 테스트용 가짜 모듈**로 비동기 호출·예산·유지·신뢰도·로그 경로를 확인했다. Jev의 실제 판단 결과와 지연 시간은 수업 전에 키로 실행해 GUIDE.md를 갱신할 것.
