# 요구사항 — 개인용 할 일 관리 웹 앱

> 03 실습의 준비된 결과 예제. 모듈 04부터 시작하는 사람이 참고할 수 있다. 아래 결정은 예제 조건이며 실제 사용자 승인 기록이 아니다.

## 목적과 범위

개인 사용자가 같은 브라우저에서 처리할 일을 기록하고, 남은 일을 찾아 이어서 처리한다. 추가·완료 전환·삭제·필터·남은 개수·목록 보존을 제공한다. 로그인, 팀 공유, 다른 기기 동기화, 서버 전송, 마감일·알림은 범위 밖이다.

용어: 미완료와 화면의 ‘진행 중’은 같은 뜻이다. 별도의 ‘진행’ 상태를 두지 않는다. ‘전체 목록’은 필터 전의 저장 대상 목록, ‘표시 목록’은 필터를 적용해 화면에 보이는 항목들이다.

## 원요청 이후의 결정

- D-01: 제목 앞뒤 공백을 제거하고 빈 값은 거부한다. 제거 후 길이는 1~200이며 JavaScript 문자열의 length 기준으로 센다. 화면에도 이 기준의 제한이 있음을 안내한다. 같은 제목은 허용한다. 항목의 동일성을 제목으로 판정하지 않는다.
- D-02: 추가 순서로 표시하고 새 항목은 미완료다. 완료를 전환해도 순서는 바뀌지 않는다.
- D-03: 삭제 확인 창과 되돌리기는 이번 범위에 넣지 않는다. 남은 개수는 필터와 무관한 전체 미완료 수다.
- D-04: 같은 브라우저·같은 주소의 정상 저장 데이터를 다시 사용한다. 브라우저 데이터를 지운 뒤, 다른 기기, 비공개 모드에서의 보존은 약속하지 않는다. 다시 열 때 필터는 전체로 시작한다.
- D-05: 변경 저장에 실패하면 변경 전 목록·개수를 유지하고 한국어 오류를 알린다. 처음 불러온 저장 내용이 손상되었으면 덮어쓰지 않고 오류를 알리며 변경 기능을 중단한다. 정상 저장소를 사용하는 새 실습 주소에서 다시 시작할 수 있다.

## 기능 요구와 인수조건

| ID | 요구사항 | 확인할 조건 |
|---|---|---|
| W-01 | 유효한 제목의 할 일을 미완료로 추가하고 추가 순서로 표시한다. | 빈 목록에 ‘보고서 작성’을 추가하면 미완료 항목 한 개와 남은 개수 1이 보인다. 완료 필터에서 추가하면 저장은 되지만 새 항목은 그 필터에 보이지 않는다. |
| W-02 | 빈 제목·공백뿐인 제목·앞뒤 공백 제거 후 길이가 200을 넘는 제목은 거부하고 이유를 한국어로 알린다. | 기존 목록에서 해당 입력으로 추가해도 항목·저장 데이터·개수가 바뀌지 않는다. 길이 200은 허용하고 201은 거부한다. |
| W-03 | 지정한 한 항목의 완료를 설정하거나 해제한다. | 같은 제목 두 개 중 하나를 완료하면 그 항목만 바뀐다. 다시 해제하면 미완료가 된다. |
| W-04 | 지정한 한 항목을 삭제한다. | 같은 제목 두 개 중 하나를 삭제해도 다른 항목은 남고 개수는 전체 미완료 수와 일치한다. |
| W-05 | 전체·진행 중·완료를 선택해 표시 목록을 바꾼다. | 미완료 A, 완료 B에서 각 필터는 A·B / A / B를 표시한다. 필터 변경은 데이터의 완료 상태나 순서를 바꾸지 않는다. |
| W-06 | 필터와 무관하게 전체 목록의 미완료 수를 표시한다. | 위 상태에서 어느 필터를 선택해도 남은 개수는 1이다. |
| W-07 | 정상 저장된 제목·완료 상태·순서를 새로 고침과 브라우저 재실행 뒤에도 복원한다. | A·B를 추가하고 A를 완료한 뒤 다시 열면 두 항목이 A, B 순서로 보이고 A의 완료가 유지된다. 초기 필터는 전체다. |
| W-08 | 저장 실패를 성공으로 표시하지 않고, 손상된 저장 내용을 조용히 덮어쓰지 않는다. | 변경 저장 실패 시 기존 목록 유지와 오류 안내를 관찰한다. 손상 데이터로 시작하면 오류와 변경 중단을 확인한다. |

## 품질 요구와 제약

| ID | 요구사항 | 확인 방법 |
|---|---|---|
| Q-01 | 키보드만으로 추가·완료·삭제·필터 선택을 할 수 있고 초점을 식별할 수 있다. | 마우스 없이 Tab, Enter, Space로 기능을 사용하고 현재 초점이 보이는지 확인한다. |
| Q-02 | 화면과 성공·거부·저장 실패 안내를 한국어로 제공한다. | 정상·오류 시나리오의 실제 문구를 읽는다. |
| C-01 | 할 일 데이터를 외부 서버로 전송하지 않는다. | 저장 설계·코드를 읽고 브라우저 네트워크 기록에서 전송 여부를 확인한다. |

## 사용자 스토리와 유즈케이스

US-01: 개인 사용자로서 남은 일을 잊지 않고 이어서 처리하도록 할 일을 등록하고 확인하고 싶다.

UC-W01 추가:
- 행위자·목표: 개인 사용자가 처리할 일을 목록에 남긴다.
- 사전조건: 앱이 열려 있고 저장 내용을 정상적으로 읽었다.
- 정상 흐름: 사용자가 제목을 입력하여 추가한다 → 시스템이 D-01로 검사한다 → 미완료 항목을 만들어 전체 목록에 추가한다 → 저장 성공 후 현재 필터로 목록과 전체 남은 개수를 표시한다.
- 대안 A: 제목이 유효하지 않으면 이유를 알리고 기존 목록과 저장 내용을 유지한다.
- 대안 B: 저장이 실패하면 변경 전 목록을 유지하고 실패를 알린다.
- 사후조건: 성공한 경우에만 새 항목이 저장되어 다음 실행에서 복원된다.

UC-W02 완료·삭제·조회:
- 사전조건: 미완료 A와 완료 B가 있는 정상 저장 목록이다.
- 사용자가 A를 완료하면 저장 성공 후 완료 필터에 A와 B가 보이고 남은 개수는 0이다.
- A를 미완료로 돌리면 완료 필터에는 B만 남고 남은 개수는 1이다.
- B를 삭제하면 완료 필터는 빈 표시 목록이 된다. 전체 필터에서는 A가 남는다.
- 완료·해제·삭제의 저장 실패도 W-08에 따라 변경 전 상태를 유지한다.

## 검토와 다음 단계

이 예제는 D-01~D-05를 선택한 상태로 04에 전달한다. 구현을 막는 미정은 없다. 실제 프로젝트에서는 사용자와 이 결정을 확인한 뒤 사용한다. 04에서 데이터 모델·저장 방식·화면 책임을 선택하되 W/Q/C ID와 인수조건의 의미를 유지한다.
