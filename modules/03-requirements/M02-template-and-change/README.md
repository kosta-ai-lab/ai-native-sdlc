# 모듈 03 · 단원 M02 — 양식으로 요구사항을 쓰고 변경 영향 찾기

> 상태: 초안 · 담당: 윤성열 · 예제: 할 일 생성(함수 하나)
> 검증 기준: Claude Code 2.1.330(모델 Sonnet 5.5) · 2026-11-24

## 목적

“팀원이 처리할 업무를 할 일로 등록할 수 있게 해 주세요.” 이 한 문장을 빈 양식에 채워 가며, 원문에 있는 사실과 AI의 제안, 사람의 결정, 아직 정하지 않은 질문을 구별해 기록합니다. 그다음 변경 요청 하나가 요구와 뒤 단계의 산출물 어디에 영향을 주는지 찾습니다.

이 단원의 뼈대는 이 과정의 네 가지 원칙입니다. 네 원칙은 ‘AI는 제안하고, 결정은 사람이 한다’, ‘말이 아니라 실행 결과로 확인한다’, ‘맡길수록 절차가 필요하다’, ‘앞 단계가 뒤 단계의 기준이다’입니다. 그래서 GUIDE의 단계는 **맡긴다·확인한다·정한다·넘긴다**의 네 마디로 나누어 적었습니다.

이 단원을 마치면 다음을 할 수 있습니다.

- 빈 양식에 원요청, 질문·가정·결정, 범위, 요구, 유즈케이스를 채운다.
- AI가 넓힌 범위를 사람의 결정으로 좁히고, 승인 근거 없이 ‘승인’이라고 쓰지 않는다.
- 변경 요청을 바로 반영하지 않고 영향받는 요구, 유즈케이스, 명세, 인수조건, 테스트, 구현을 먼저 목록으로 만든다.

## 이 단원에서 다루는 것

| 구분 | 내용 |
|---|---|
| 개념 | 원문 사실·가정·결정·미결의 구별, 유즈케이스와 요구의 관계, 변경 영향 |
| 실습 | 양식 채우기, 답을 반영하고 범위 좁히기, 예제와 비교, 변경 영향 찾기, 다음 단계로 넘기기 |
| 실습 예제 | 원요청 한 문장 [INPUT.md](INPUT.md). 저장소의 작은 사례인 [할 일 생성 샘플](../../../samples/web-task-system/README.md)과 같은 기능입니다 |
| 필요한 도구 | Claude Code, git, 편집기. 문서 실습만 하므로 Node.js나 웹 서버는 필요하지 않습니다 |

단원 M01은 웹 앱 하나의 요구사항 전체를 다루고, 이 단원은 기능 하나를 양식에 맞춰 쓰고 변경 영향까지 찾습니다. 어느 쪽을 먼저 해도 됩니다.

## 사전 준비물

- Claude Code. 설치와 로그인을 마친 상태여야 합니다. `claude --version`으로 확인합니다. 설치 방법은 Claude Code 공식 문서(https://code.claude.com/docs)를 따릅니다.
- git. AI가 고친 곳을 확인하는 데 씁니다.
- Markdown 파일을 읽고 고칠 편집기.

## 완료 기준

- [ ] 원문, 가정, 결정, 미결이 구별된 `requirements.md`가 있다.
- [ ] 결정마다 결정 주체와 이유가 있고, 내가 정하지 않은 결정은 ‘제안’으로 남아 있다.
- [ ] 요구 ID마다 확인 기준이 있고 유즈케이스의 정상 흐름과 오류 흐름에 연결된다.
- [ ] 변경 요청의 영향 목록이 있고, 승인 전에는 요구 본문을 고치지 않았다.

## 검증 기록 (2026-11-24)

- 환경: macOS, Claude Code 2.1.330(모델 Sonnet 5.5), git 2.56.1
- GUIDE 1·2·4단계의 요청을 Claude Code 비대화형 모드(`claude -p`)로 두 번씩, 2단계의 범위를 좁히는 요청을 한 번 실행했습니다. 합계 7회입니다. 단계마다 새 세션이고 단계 사이에는 파일만 이어졌습니다.
- 설정 파일은 프로젝트 것만 읽게 했고(`--setting-sources project,local`), 사용자 전역 지침 파일은 읽지 않게 했습니다(`claudeMdExcludes` 설정). 지침 파일이 하나도 읽히지 않는 것을 따로 확인했습니다.
- 확인한 것은 다음과 같습니다. 결과는 GUIDE 1·2·4단계의 ‘검증 실행에서 본 것’에 적었습니다.
  - 단계마다 어떤 파일이 바뀌는지(`git status`)와 원요청이 그대로인지
  - 양식의 구성이 유지되는지
  - 결정 주체, 승인 근거, 비기능 수치를 지어내는지
  - 답하지 않은 질문이 미결로 남는지
  - 변경 요청에서 요구 본문을 고치는지
- 한계: 실행 횟수가 적고 모델과 버전이 하나입니다. 다른 운영체제, 대화형 화면에서의 표시, 한 세션에서 이어서 진행하는 경우, 다른 AI 도구는 확인하지 않았습니다. 0단계의 명령은 macOS 터미널 기준입니다. 3단계와 5단계는 사람이 하는 단계라 AI 실행으로 검증하지 않았습니다.
- [SAMPLE.md](SAMPLE.md)의 원요청, 답변, 결정은 수업용으로 만든 시나리오이며 이 검증 실행의 출력이 아닙니다. 실제 고객의 요구나 승인 기록도 아닙니다.
