# 개념

**Research Assistant 하네스**는 Claude Code 안에서 **학술 연구 보조 전문가 5명이 팀으로 협업**하도록 미리 설정해 놓은 구성 파일 묶음입니다.

"문헌 리뷰 해줘"라고 한 마디만 하면, 아래 5명의 에이전트가 순서대로(일부는 동시에) 일합니다.

| 에이전트 | 하는 일 |
|---------|--------|
| 🔍 literature-searcher | 논문·서적·보고서를 웹에서 검색하고 관련성 평가 |
| 📝 note-taker | 문헌별로 구조화된 읽기 메모 작성 (핵심 논지, 방법론, 인용 구절) |
| 🧠 critic-synthesizer | 비판적 분석, 테마별 종합, 연구 갭(gap) 식별 |
| 📚 reference-manager | APA/MLA/Chicago 등 인용 형식 관리, BibTeX 생성 |
| ✅ research-coordinator | 전체 결과물 교차 검증 후 최종 보고서 작성 |

최종적으로 `_workspace/` 폴더에 **문헌 검색 결과 → 읽기 메모 → 비평·종합 → 참고문헌 → 최종 연구 보고서** 5개의 마크다운 파일이 만들어집니다.

> ⚠️ **범위 참고**: 실험 수행, 통계 분석 실행, 논문 최종 집필, 학술지 투고는 이 하네스의 범위가 아닙니다. "연구 준비 단계"를 도와주는 도구입니다.

# 1 단계:환경 설정

1. **Claude Code 설치** — 터미널에서 실행되는 Anthropic의 AI 코딩 도구입니다.

   ```bash
   npm install -g @anthropic-ai/claude-code
   ```

   > Node.js 18 이상이 필요합니다. 설치 여부는 `node -v`로 확인하세요.
   > 설치 후 터미널에서 `claude`를 입력하면 로그인 안내가 나옵니다 (Claude Pro/Max 구독 또는 API 키 필요).

2. **Git 설치** (하네스 다운로드용) — `git --version`으로 확인. 없다면 [git-scm.com](https://git-scm.com)에서 설치하거나, 아래 4단계의 "Git 없이 받기" 방법을 사용하세요.

# 2 단계: 작업 폴더 만들기

연구 자료가 저장될 폴더를 하나 만듭니다.


# 3 단계: code-reviewer.md 파일로 첫 번째 에이전트 만들기

서브에이전트는 자기만의 독립된 대화 공간(컨텍스트)과 시스템 프롬프트, 도구 권한을 가진 별도의 Claude입니다. 메인 대화를 어지럽히지 않고 일을 맡긴 뒤 결과만 돌려받을 수 있습니다. .claude/agents/code-reviewer.md 파일을 만들고 아래 내용을 붙여 넣으세요.

```bash
---
name: code-reviewer
description: 코드 변경 사항을 검토한다. 사용자가 코드 리뷰, 검토,
  review를 요청하거나 커밋 직전 품질 확인이 필요할 때 사용한다.
tools: Read, Grep, Glob, Bash
---
 
당신은 꼼꼼한 시니어 코드 리뷰어입니다.
 
호출되면 다음 순서로 작업하세요.
 
1. `git diff HEAD` 를 실행해 최근 변경 사항을 확인한다.
2. 다음 관점에서 문제를 찾는다.
   - 버그 가능성 (오타, 잘못된 조건문, null 처리 누락)
   - 보안 문제 (비밀번호/키 하드코딩, 입력값 검증 누락)
   - 가독성 (모호한 변수명, 중복 코드)
3. 발견한 문제를 심각도(높음/중간/낮음)로 나눠 보고한다.
   각 항목에 파일명과 줄 번호를 포함한다.
4. 각 문제에 대해 최소한의 수정 방법을 제안한다.
 
중요: 파일을 직접 수정하지 말고 보고서만 작성하세요.
```

## 규칙

스킬과 형식이 거의 같지만 결정적 차이가 하나 있습니다. 바로 tools 항목입니다. 이 에이전트에게는 읽기(Read), 검색(Grep, Glob), 명령 실행(Bash)만 허용하고 파일 쓰기/수정 도구(Write, Edit)는 주지 않았습니다. 리뷰어가 실수로 코드를 고쳐버리는 일을 구조적으로 막은 것이죠. 이것이 하네스 엔지니어링의 핵심 사고방식입니다. "하지 마"라고 부탁하는 대신, 애초에 할 수 없게 설계합니다.

프런트매터 아래의 본문은 이 에이전트의 시스템 프롬프트가 됩니다. 에이전트는 메인 대화 내용을 전혀 모르는 상태로 시작하므로, 본문에 '호출되면 무엇부터 할지'를 스스로 알아낼 수 있게 적어야 합니다. 위 예제에서 1번 단계가 git diff HEAD 실행인 이유가 바로 이것입니다.

