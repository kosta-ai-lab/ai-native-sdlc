# 모듈 06 · 단원 M02 — 규칙으로 고정하기

> 상태: 초안 · 담당: 윤성열
> 검증 기준: Claude Code 2.1.330(모델 Sonnet 5.5) · Vitest 3.2.6 · TypeScript 5.9.3 · pnpm 12.21.0 · Node.js v24.22.0 (2026-11-24)

## 목적

단원 M01에서 프롬프트로 일러 준 순서를 **규칙 파일(`CLAUDE.md`)**에 적어 둔다. 같은 요청을 규칙 없이 한 번, 규칙을 넣고 한 번 실행해 AI가 일하는 순서와 보고가 어떻게 달라지는지 직접 기록한다.

이 단원을 마치면 다음을 할 수 있다.

- 이 모듈의 TDD 규칙 조각을 프로젝트의 `CLAUDE.md`에 넣는다.
- AI의 작업을 도구 호출 순서와 `pnpm test` 출력으로 관찰하고 기록한다.
- 보고에 적힌 Red를 그대로 믿지 않고 직접 재현한다.
- 통과시키려고 테스트를 고치는 일(테스트 세탁)을 `git status`로 찾아낸다.
- 규칙이 바꾸는 것과 바꾸지 못하는 것을 구분해 말한다.

## 검증 기록 (2026-11-24)

- 환경: macOS, Node.js v24.22.0, pnpm 12.21.0, Vitest 3.2.6, TypeScript 5.9.3, Claude Code 2.1.330(모델 Sonnet 5.5)
- 같은 프롬프트를 규칙이 없는 폴더와 있는 폴더에서 Claude Code 비대화형 모드(`claude -p`)로 실행했다. 설정 파일은 프로젝트 것만 읽게 했다. 사용자 전역 지침 파일(`~/.claude/CLAUDE.md`)은 두 조건 모두에서 함께 읽혔다. 그 파일에는 실행 장비의 환경 안내만 있고 TDD나 테스트에 관한 규칙은 없다.
  - 새 시나리오 두 개 구현: 조건마다 3회
  - 테스트가 없는 새 저장소에서 시나리오 두 개 구현: 조건마다 2회
  - "빨리 통과만 시켜줘": 조건마다 2회
- 도구 호출 순서는 실행 기록에서, 결과는 `git status`와 `pnpm test`로 확인했다. 조건별 결과는 [GUIDE.md](GUIDE.md#규칙이-있을-때와-없을-때-검증-실행에서-본-것)의 표에 있다.
- GUIDE.md 1, 3, 5, 6단계의 명령(복사, 설치, stash, sed)을 직접 실행했다. 예상 출력은 그 결과에서 옮겼다.
- 한계: 실행 횟수가 적고 모델과 버전이 하나다. 통계적 결론이 아니라 관찰 기록이다. 대화형 화면에서의 표시는 확인하지 않았다.
