# 규칙 — 코딩 단계에서 AI가 지킬 것 (TDD)

> 이 파일은 코딩 단계에서 에이전트의 행동을 제약하는 규칙이다. 프로젝트 루트의 CLAUDE.md에 이 조각을 포함하거나 import 해서 쓴다.

## 절대 규칙

1. **새 기능은 반드시 실패하는 테스트부터.** 테스트 없이 소스 코드를 작성·수정하지 않는다.
2. **인수 조건을 테스트로 1:1 매핑.** 모듈 05(BDD)의 Given·When·Then을 그대로 테스트 케이스로 옮긴다. 인수 조건에 없는 기대 동작을 테스트에 추가하지 않는다.
3. **Red를 먼저 확인.** 구현 전 테스트가 실패하는 것을 보고 나서 구현한다.
4. **최소 구현.** 통과에 필요한 최소 코드만 생성한다. 스펙·인수 조건에 없는 기능을 임의로 덧붙이지 않는다(환각 금지).
5. **한 번에 한 기능.** 테스트가 통과하기 전에는 다음 기능으로 넘어가지 않는다.
6. **테스트를 무르게 고치지 않는다.** 테스트가 실패하면 구현을 고친다. 통과를 위해 단언(assertion)을 약화하지 않는다.

## 작업 순서 (에이전트에게)

```
1. 입력 스펙·인수 조건을 읽는다.
2. 인수 조건마다 테스트 케이스를 작성한다.
3. 테스트를 실행해 실패(Red)를 확인한다.
4. 테스트를 통과하는 최소 코드를 작성한다.
5. 테스트를 실행해 통과(Green)를 확인한다.
6. 테스트를 통과한 채로 리팩터한다.
7. 다음 인수 조건으로 넘어간다.
```

## 금지

- 테스트보다 소스를 먼저 작성하는 것
- 스펙에 없는 동작·필드·엔드포인트를 지어내는 것
- 여러 기능을 한꺼번에 구현해 실패 지점을 가리는 것
