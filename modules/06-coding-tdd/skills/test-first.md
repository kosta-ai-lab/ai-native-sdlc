# 자동화 — test-first (스킬·서브에이전트 명세)

> Claude Code에서 TDD 흐름을 자동으로 돌리는 스킬/서브에이전트의 명세. 공개 런칭 시 실제 `SKILL.md`와 서브에이전트 정의로 구현한다.

## 무엇을 하는가

인수 조건(BDD 산출물)을 입력받아, 테스트 우선 루프를 자동으로 진행한다.

1. 인수 조건을 테스트 케이스로 변환한다.
2. 테스트를 실행해 실패를 확인한다.
3. 통과하는 최소 구현을 생성한다.
4. 테스트를 다시 실행해 통과를 확인한다.
5. 통과하지 못하면 구현만 수정해 반복한다(테스트는 건드리지 않는다).

## 입력 / 출력

| 입력 | 출력 |
|------|------|
| 인수 조건(Gherkin), 대상 모듈 경로 | 테스트 파일, 구현 파일, 실행 결과 요약 |

## 호출 예 (개념)

```
/test-first --spec docs/acceptance/todo-create.feature --target src/todo
```

## 서브에이전트 분리 (선택)

대규모 작업에서는 역할을 나눈다.

| 서브에이전트 | 역할 |
|-------------|------|
| test-writer | 인수 조건을 테스트로 변환만 한다(구현 접근 금지) |
| implementer | 테스트를 통과하는 구현만 한다(테스트 수정 금지) |
| reviewer | 테스트와 인수 조건의 1:1 대응을 검증한다 |

> 핵심 안전장치: **test-writer와 implementer를 분리**해, 구현하는 에이전트가 테스트를 무르게 고치지 못하게 한다.

## 훅 연계

- pre-commit 훅: 테스트가 모두 통과하지 않으면 커밋을 막는다.
- 모듈 08(CI)의 게이트와 동일한 기준을 로컬에서 먼저 적용한다.
