# 모듈 06 · 단원 M01 — Red → Green → Refactor 한 바퀴

> 상태: 초안 · 담당: 윤성열
> 검증 기준: Vitest 3.2.6 · TypeScript 5.9.3 · pnpm 12.21.0 · Node.js v24.22.0 · Claude Code 2.1.330 (2026-11-24)

## 목적

인수조건 두 개를 **테스트 목록 → 실패하는 테스트 → 최소 구현 → 다듬기** 순서로 직접 구현해 본다. Claude Code에게 단계를 하나씩 맡기고, 단계마다 `pnpm test` 출력으로 결과를 확인한다.

이 단원을 마치면 다음을 할 수 있다.

- 인수조건에서 테스트 목록을 만들고, 한 번에 한 항목만 테스트로 옮긴다.
- 파일을 불러오지 못한 **오류**와 단언이 실패한 **유효한 Red**를 출력에서 구분한다.
- 실패한 테스트를 통과하는 최소 구현만 받고, 인수조건 밖의 코드를 걸러 낸다.
- 테스트를 건드리지 않고 구현을 다듬는다.

## 이 단원에서 다루는 것

| 구분 | 내용 |
|---|---|
| 절차 | Kent Beck의 Canon TDD 다섯 단계 |
| 판정 | 유효한 Red의 세 가지 조건 (오류가 아닌 실패, 예상한 메시지, 기능이 없어서 실패) |
| 실습 예제 | `todo-app`: 할 일 생성 기능의 인수조건 두 개 |
| 도구 | TypeScript, Vitest, pnpm, Claude Code |

## 검증 기록 (2026-11-24)

- 환경: macOS, Node.js v24.22.0, pnpm 12.21.0, Vitest 3.2.6, TypeScript 5.9.3, Claude Code 2.1.330(모델 Sonnet 5.5)
- GUIDE.md 1~8단계의 명령을 직접 실행했다. 문서의 예상 출력은 이 실행 결과에서 옮겼다.
- 프롬프트 여섯 개를 Claude Code 비대화형 실행(`claude -p`)으로 한 세션에서 차례로 실행했다. 여섯 번 모두 요청한 범위만 수행했고, 마지막에 테스트 2개가 통과했다.
- 확인하지 않은 것: 다른 운영체제, 다른 모델, 20 계열과 22 계열 Node.js. AI의 응답과 생성 코드는 실행마다 달라질 수 있어, 단계마다 출력으로 확인할 항목을 두었다.
