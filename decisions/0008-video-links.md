# ADR 0008 — 영상 자료는 유튜브 주소로만 연결한다

- 상태: Accepted
- 날짜: 2026-11-26
- 결정한 사람: 메인테이너 윤성열(Andy)

## 맥락

사이트가 여는 바깥 주소는 이 저장소의 GitHub 주소뿐이었다([ADR 0006](0006-learning-roadmap-site.md)). 강사가 유튜브 채널 토크아이티(Talk IT)에 나와 이야기한 영상이 있다. 메인테이너는 영상도 교육 내용이므로 사이트에서 따로 다루고 링크를 관리해야 한다고 판단했다. 영상은 채널의 것이고 이 저장소에 없다.

## 결정

1. 사이트에 영상 자료 화면(`videos.html`)을 둔다. 영상은 옮겨 오거나 화면에 끼워 넣지 않고 유튜브의 영상 주소로만 연결한다. 미리보기 그림도 불러오지 않는다.
2. 목록은 `site/data/videos.json` 한 파일에서 관리한다. 주소는 통째로 적지 않고 영상 번호만 적는다. 화면이 만들 수 있는 바깥 주소는 유튜브의 영상 주소와 채널 주소 둘뿐이고, 검사가 이를 확인한다.
3. 제목, 올라온 날, 길이는 유튜브에서 읽은 값을 적는다. 화면에 보이는 제목은 원래 제목에서 회차와 출연자 표기, `#shorts`를 떼고, 붙어 버린 낱말의 띄어쓰기와 철자 오타만 바로잡는다. 주제는 사이트에서 나눈 것이다.
4. 주소가 열리는지는 `npm run check:videos`로 확인한다. 네트워크가 필요하므로 CI의 검사에는 넣지 않는다.

## 근거

- 영상을 끼워 넣거나 미리보기 그림을 쓰면 방문자의 브라우저가 유튜브에 요청을 보낸다. 지금의 meta CSP(같은 출처만 허용)와 "추적과 외부 요청이 없다"는 원칙을 그대로 두려면 링크만 두어야 한다.
- 영상의 권리는 채널에 있다. 제목을 적고 주소로 연결하는 것은 영상을 옮겨 싣는 것이 아니다.
- 주소를 통째로 적게 하면 다른 사이트의 주소가 섞여 들어올 수 있다. 영상 번호만 받으면 그럴 수 없다.
- CI에서 바깥 사이트에 물으면 유튜브의 응답에 따라 병합이 막힐 수 있다. 확인은 필요할 때 사람이 돌린다.

## 결과

- 영상이 내려가거나 제목이 바뀌어도 사이트는 스스로 알지 못한다. `check:videos`를 돌려야 알 수 있다. 그래서 화면 아래에 주소를 마지막으로 확인한 날을 적는다.
- 다른 강사의 영상과 다른 채널도 같은 파일에 더할 수 있다.
- 유지하는 것: 엄격한 meta CSP, 상대 경로, 재현 가능한 빌드, 화면은 DOM API로만 만든다, 추적과 외부 요청이 없다.
